## Conventions used by the rows

- Module `tools/mcp-insight/insight_tools.py`, FastMCP server name `tdn-insight`, stdio only.
- Environment:
  - `INSIGHT_MCP_APP_DB`: the app SQLite file. Required by `build_warehouse`. It has no default.
  - `INSIGHT_MCP_APP_ARTIFACTS`: the artifact root (`sha256/<2 chars>/<sha>`). Default: `artifacts/` next to the app DB.
  - `INSIGHT_MCP_APP_CAPTURES`: the app's metric capture root, which holds the run scope record
    `<capture root>/<run_id>/scope.json`. Default: `metric-captures/` next to the app DB (the app's own default when
    `TDN_METRIC_CAPTURE_DIR` is unset). Read only.
  - `INSIGHT_MCP_DATA_DIR`: where the run warehouses live. Default: `tools/mcp-insight/out/` (gitignored).
  - `INSIGHT_MCP_ALLOW_PAID`: exactly `1` allows a real Jev call. Any other value refuses.
  - `INSIGHT_MCP_JEV_KEY_FILE`: key file holding a `TYPESAFE_API_KEY=` line. Default: the project secret file under
    `~/.config/tdn-growth-os/secrets/`.
- "App home" in the rows means the app DB file, its `-wal`/`-shm` siblings, the artifact root, the capture root with
  its scope records, and every other file in the app DB's directory (for example a synthetic config file or `.env` in a
  fixture).
- Warehouse: one SQLite file per run, `<data dir>/runs/<run_id>.sqlite`.
- Platforms: `shopee` and `tiktok_shop` for reviews, `google` for keywords and Trends.
- The Jev transport is one injectable function. Tests replace it with a fake that counts calls and records request
  bodies. There is no real network in any test. Fake-transport tests of the paid branch are offline checks, not Jev
  calls.
- Fixtures are synthetic. They contain no real review text, names or IDs. Every synthetic review text contains a
  unique nonce token (for example `zqv01`). Some reviews are short (the nonce plus one or two words), so a leak check
  can find a whole short review, not only long runs of words.
- The five PR 1 tools and their only arguments (PR 2 adds four tools, IM-Q52):
  - `build_warehouse(run_id)`.
  - `code_reviews(run_id, dry_run=True, max_calls=None, block_override=None)`.
  - `theme_counts(run_id, question=None)`.
  - `keyword_counts(run_id)`.
  - `portrait_counts(run_id)`.
- Errors are returned as `{"error": "<CODE>", "message": "<text>"}`. An error result has no count fields.

## PR 2 conventions (R-IM07 to R-IM09)

- New data file `tools/mcp-insight/data/report-frame.json`: the 18 parts (R-I30, R-I31), the source role table
  (R-I34), the cells where a source answers only part of a question (R-I32) and the TikTok Shop revenue gate (R-I34).
  It holds exactly the data frozen in "Frozen report frame" below. The module path constant is `REPORT_FRAME_PATH`;
  tests point it at a copy.
- New shared store `<data dir>/insight-shared.sqlite` (design decision 6). It holds evidence from people that a run
  warehouse cannot hold. No table holds review text. Tables:
  - `sample_review(rules_kind, rules_version, reviewed_by, reviewed_at, sample_size, passed)`: an owner review of a
    sample of an automatic classification. `rules_kind` is `codebook`, `keyword_groups` or `portrait_rules`.
  - `method_ledger(method_key, subject_key, run_id, approved_by, approved_at)`: one row per owner-approved report
    that used a method, on one researched product (`subject_key`, for example `canxi`). `method_key` is
    `<tool>:<source key>:<rules version>`, for example `theme_counts:shopee_reviews:2026-10-30.4`.
  - `diversity_check(count_id, brands, checked_by, checked_at)`: a person checked that the data behind one count ID
    comes from `brands` distinct brands (R-I32 check 2, «không chỉ dựa vào một sản phẩm hay một thương hiệu»).
  - `revenue_share(run_id, platform, share_percent, recorded_by, recorded_at)`: a platform's share of revenue for the
    run (0 to 100), copied by the owner or the coordinator from the Market numbers. No tool computes it, and no
    provider is called for it.
  - `reason_check(run_id, review_id, theme_pair, text_sha256, linked, checked_by, checked_at)`: a person read the
    review on the host machine (`read_reviews`) and judged whether the customer joins the two themes with a reason
    (`linked` 1) or not (`linked` 0). `theme_pair` is the two theme codes sorted and joined by `|`. `text_sha256` is
    the sha256 (hex) of the UTF-8 bytes of the review's `review_text.text` that was read, taken from the warehouse when
    the reading is recorded. A reading applies only while the review's current text has that hash.
  Only five module functions write it, one per table: `record_sample_review`, `record_method_approval`,
  `record_diversity_check`, `record_revenue_share` and `record_reason_check` (IM-Q77), for the owner or the
  coordinator. They are not MCP tools. No MCP tool writes the shared store, and no tool creates it when it is missing
  (a missing store reads as empty). `run_id` in the store is always the full run ID. When several rows have the same
  key (`revenue_share` per run and platform, `diversity_check` per count ID, `reason_check` per run, review, pair and `text_sha256`),
  the latest inserted row applies.
- Confidence levels, high to low: `Chắc`, `Khá`, `Yếu`, `Không` (R-I32). Labels: `Khung`, `Chưa có dữ liệu`,
  `Giả thuyết`.
- A "count row" is one row of `theme_counts`, `keyword_counts` or `portrait_counts` with its `count_id`. Its
  source is: `shopee_reviews` or `tiktok_shop_reviews` by the row's platform (theme and portrait rows), or
  `search_suggestions` (keyword rows). Its step is the row's own step (R-I31): `Sau mua` for theme and portrait rows,
  the keyword group's step for keyword rows (so `cach_dung` and `khac` rows are `Chưa rõ bước`).
- A count ID is "current" when the producing tool, called now on the same run, returns a row with that ID.
- Hidden names (R-L01, R-I29). The module constant `HIDDEN_NAMES` holds the 26 names of `HIDDEN_NAMES` in
  `src/modules/analysis/report-language/hidden-names.ts`, plus `World Bank` and `SLAYER`:
  - DATA: `Metric`, `Kalodata`, `TradeInt`, `Dami`.
  - TOOL: `SerpApi`, `Apify`, `PageIndex`, `Agent-Reach`, `OpenCLI`, `zen-studio`.
  - AI_SEARCH: `Jev`, `TypeSafe`, `CLIProxy`, `OpenAI`, `Anthropic`, `GLM`, `Gemini`, `Google`, `Nemotron`, `NVIDIA`.
  - PUBLIC_REVIEW: `CloakBrowser`, `Cloak Browser`, `cloak-browser`, `cloak_browser`, `ShopeePublicReviewCollector`,
    `shopee-public-review`.
  Matching is that file's READER rule: a whole name with Unicode edges (no letter, digit or `_` right before or
  after), case-insensitive, except `Metric`, which matches only `Metric` and `METRIC` (lowercase `metric` is
  allowed); plus model IDs `(gpt|claude)-` followed by a letter or digit, case-insensitive. `Shopee` and
  `TikTok Shop` are allowed. The module imports no app code; a test reads the TS file as text and checks that every
  app name is in the module list.

## PR 3 conventions (R-IM10 to R-IM12, task 4.4)

- Three new tools (IM-Q79): `submit_section(run_id, part, text, claims)`, `submit_statement(run_id, statement,
  replaces=None)` and `render_report(run_id)`.
- New report store `<data dir>/insight-report.sqlite` («SQLite lưu trữ» of R-IM12, the MCP's own file, never the app
  DB). Only the three new tools write it, and only on success: an accepted section, an accepted statement, or a
  render. Tables:
  - `section_version(run_id, part, version, text, claims_json, graded_json, frame_version, codebook_version,
    submitted_at)`, primary key `(run_id, part, version)`.
  - `statement_version(statement_id, version, run_id, step, statement_json, evidence_json, app_payload_json,
    codebook_version, submitted_at)`, primary key `(statement_id, version)`.
  - `render_archive(archive_id, run_id, html, totals_json, statements_json, codebook_version, frame_version,
    rendered_at)`, primary key `archive_id`.
  Each table has `BEFORE UPDATE` and `BEFORE DELETE` triggers that abort: a stored row is never changed or removed.
  `run_id` is always the full run ID. No column holds review text (IM-Q81).
- Report files: `render_report` writes `<data dir>/reports/<full run id>/` with `report.html`, `themes.json`,
  `keywords.json`, `portraits.json` and `parts.json` (IM-Q102, IM-Q104). It writes nothing else.
- Clock: the three new tools read the time only through the module function `insight_tools._now()` (UTC). Tests
  replace it to give fixed, distinct instants (IM-Q105). The time goes only into `submitted_at` and `rendered_at`.
- Current count IDs. As in IM-Q62, a count ID is current when the count tool, called now on the run, returns a row
  with that ID. The new tools work out the current rows on a per-call byte copy of the warehouse (as
  `confidence_ceiling` does), so the warehouse file is not changed (IM-Q80). A reason-link ID (`find_reason_links`
  in `count_registry`) is current when `find_reason_links` for its stored pair, run on that copy, returns it.
- The numbers of a count ID are the integer values of its `count_registry.numbers_json` under the keys `reviews`,
  `writers`, `products`, `keywords` and `threshold_count` (booleans are not numbers; the list `review_ids` of a
  reason-link row is not a number). Its threshold is `numbers_json.threshold_met` when that key exists; a reason-link
  row has none. The denominator of a theme row is the `coded_reviews` value of the row's platform in the same
  `theme_counts` response (source metadata, not stored in `numbers_json`); other rows have no denominator.
- Scope numbers of a run (for frame parts 2 and 3, IM-Q84, IM-Q121): each scope number has a unit, a platform
  (`shopee`, `tiktok_shop` or none) and a measure. Per platform: the `source_status.row_count` of its review source
  (unit `đánh giá`, measure `collected`), its `coded_reviews` (unit `đánh giá`, measure `coded`) and its `product`
  row count (unit `sản phẩm`, measure `collected`). The keyword source's `row_count` (unit `từ khóa`, platform none,
  measure `collected`).
- Scope binding (frame parts 2 and 3, IM-Q121). A clause is a part of a sentence cut at each `,`, `;` and `:`. For a
  number token or fraction with a unit, its platform is the platform named in its clause (a whole phrase `shopee` or
  `tiktok shop`), or, when the clause names none, the platform named in its sentence; it is unbound when the place
  it is read from names both platforms or neither. Its measure is `coded` when its clause holds a whole phrase of
  `CODED_WORDS` (`mã hóa`, `mã hoá`, `gắn nhãn`), otherwise `collected`. Only affirmative scope forms are supported
  (revision 14): when the clause holds a whole word of `SCOPE_NEGATIONS` (`không`, `chưa`, `chẳng`, `chả`), the number
  has no supported measure and fails `NUMBER_MISMATCH`, whatever its value. The uncoded remainder is not a scope
  number. Split context (revision 15): measure and negation words are never dropped by the cut. When the number's
  own clause holds no `CODED_WORDS` phrase and an earlier clause of the same sentence holds a `CODED_WORDS` phrase or
  a `SCOPE_NEGATIONS` word (for example a heading before `:`), the number has no supported measure and fails
  `NUMBER_MISMATCH`; it is never read as `collected` by default. Each number states its measure in its own clause.
- Steps: the six report steps `Biết đến`, `Quan tâm`, `Muốn mua`, `Mua`, `Sau mua`, `Chưa rõ bước` (frozen frame
  order). A statement takes one of the first five (R-C01).
- Confidence levels: `Chắc`, `Khá`, `Yếu`, `Không` (R-I32). A level is above a ceiling when it is higher in this
  order.
- Review-derived rows: theme rows, portrait group rows («Ai dùng», «Mua cho ai») and reason-link rows. Keyword rows
  and portrait gender and age rows are not review-derived customer words.
- Kept kinds (R-I39, R-I22, R-L12; IM-Q113): `KEPT_KINDS` maps the four allowed kinds of motive and barrier to core
  theme codes of the codebook: công dụng `T-CONGDUNG`, giá `T-GIA`, quy cách `T-QUYCACH`, chất lượng `T-CHATLUONG`. No
  other theme (core or block) is a kept kind. The map is frozen in the module; a new codebook version does not change
  it. A reason-link row backs a motive or barrier only when both of its themes are kept kinds (IM-Q122).
- Text rules. They are applied to `nz(text)` (NFC, then lower case) unless stated:
  - Marker: `[^<ref>]`, where `<ref>` matches `^[a-z0-9][a-z0-9_-]{0,15}$`. Markers are removed before the number,
    quote and phrase checks.
  - Line and heading: the text is cut into lines at each line break. A heading is a line `#{1,3} <title>` that holds
    no marker and no number token and whose `<title>`, after `nz` and with surrounding spaces removed, equals one of
    the structural titles (revision 13, IM-Q120): the frozen title of the submitted part, a step name of the six
    steps, `shopee`, `tiktok shop`, the frozen name of a frame source, a theme name of the run's codebook, or a group
    name of the frozen keyword groups. Any other line that starts with `#` is not a heading: it is cut into
    sentences like any line.
  - Sentence: each line is cut after each `.`, `!`, `?` or `…` that is followed by whitespace or by the end of the
    line. A sentence "has" a marker when the marker was in it before removal. A heading is not a sentence.
  - Number token: `\d+(?:[.,]\d+)*` (ASCII digits) not preceded by a letter, digit, `_` or `-` (so `R-I33`,
    `zqv01`, `IMC-1a2b…` hold no number token). Value: a token that matches `^\d{1,3}(?:\.\d{3})+$` is an integer
    with the dots removed (`1.248` is 1248); any other token with `.` or `,` is not an integer; a plain digit run is
    an integer. A token right after a whole word `phần`, `câu` or `tầng` (optional spaces) is a reference
    («Phần 8», «câu 3»), not a number token.
  - Fraction: two number tokens joined by `/` with no space (`6/40`) form one fraction `n/N`. Three or more tokens
    joined by `/` (a date such as `30/10/2026`) are not a fraction; each is a token with no unit.
  - Unit: the whole phrase right after a number token or fraction (optional spaces): `UNIT_WORDS` `đánh giá` →
    `reviews`, `người viết` → `writers`, `sản phẩm` → `products`, `từ khóa` or `từ khoá` → `keywords`. A token followed
    by `%` or by the phrase `phần trăm` has the unit `percent`. Any other token has no unit.
  - Number word: a whole word of `NUMBER_WORDS` (`một`, `hai`, `ba`, `bốn`, `năm`, `sáu`, `bảy`, `tám`, `chín`,
    `mười`, `mươi`, `chục`, `trăm`, `nghìn`, `ngàn`) followed (optional spaces) by a `UNIT_WORDS` phrase.
  - Binding: in a sentence that has markers, a number token or fraction binds to the first marker after it in the
    same sentence, or, when there is none after it, to the last marker before it.
  - Words: the maximal runs of `[^\W_]` (Unicode letters and digits) in `nz(text)`. Diacritics are kept;
    punctuation, symbols and spacing are not words (design decision 8).
  - Whole phrase: a frozen phrase matches when it occurs with no letter, digit or `_` right before or after it.
  - Denial (revision 13, IM-Q123): a sentence is a denial for a gate only when it has this complete form. Its words
    are, in order: a subject of `DENIAL_SUBJECTS` (`báo cáo`, `báo cáo này`, `phần này`, `số liệu`, `dữ liệu`), then
    one whole word `không` or `chưa`, then 0 to 2 words of `DENIAL_LINKS` (`tính`, `đưa`, `ra`, `nêu`, `có`, `dùng`,
    `làm`, `đề`, `xuất`, `gợi`, `ý`, `đo`, `so`, `sánh`), then the first match of that gate's phrases. Also: the
    sentence holds exactly one whole word `không` or `chưa`; it holds no `,`, `;` or `:`; it holds no whole word of
    `DENIAL_STOP` (`nhưng`, `mà`, `và`, `còn`, `thì`, `rồi`, `nên`, `hãy`, `cần`, `vẫn`); and it has no number token,
    no fraction and no marker. Any other sentence that matches the gate's phrases is not a denial, whatever its
    negation words (for example «không ít», «không chỉ»).
  - Missing-data sentence (revision 14, IM-Q120): after `nz`, the whole sentence is `chưa có dữ liệu`, then
    optionally `về <topic>` or `cho <topic>`, then optionally `trên <platform>` or `ở <platform>`, then an optional
    final `.`, `!` or `…`, with single spaces and nothing else. `<platform>` is `shopee` or `tiktok shop`. `<topic>`
    is exactly one entry of the closed table `NO_DATA_TOPICS`: a frozen part title, a step name, a frozen frame source
    name, a theme name of the run's codebook, a frozen keyword group name, a portrait dimension name (`ai dùng`,
    `mua cho ai`, `giới tính`, `tuổi`), or one of `người mua thật`, `lý do mua`, `doanh thu`, `thị phần`. No other
    words are allowed, so the topic cannot carry an assertion.
- Frozen phrase lists (after `nz`):
  - `CONVERSION_PHRASES`: `chuyển đổi`, `conversion`, `tỷ lệ chuyển`, `tỉ lệ chuyển`; plus the pattern
    `từ <step> (sang|đến|tới) <step>` where each `<step>` is one of `biết đến`, `quan tâm`, `muốn mua`, `mua`,
    `sau mua` and the two steps differ.
  - `MARKET_TERMS`: `doanh thu`, `doanh số`, `thị phần`, `gmv`, `revenue`, `market share`.
  - Currency amount: a number token followed (optional spaces) by an optional scale `k`, `nghìn`, `ngàn`, `triệu`,
    `tr`, `tỷ`, `tỉ` and then a unit `đ`, `₫`, `vnđ`, `vnd`, `đồng`; or a number token followed directly by `k`
    (`150k`).
  - `STAR_TERMS`: a number token followed (optional spaces) by `sao`, `★` or `⭐`; and the phrases `số sao`,
    `điểm sao`, `sao trung bình`, `điểm đánh giá`, `rating`, `★`, `⭐`.
  - `RANK_TERMS`: `xếp hạng`, `hạng`, `cao hơn`, `thấp hơn`, `tốt hơn`, `kém hơn`, `hơn`, `đứng đầu`, `dẫn đầu`,
    `top`, `nhất`.
  - `BUYER_TERMS`: `người mua`, `buyer`, `buyers`.
  - `FIRST_PERSON`: `tôi`, `mình`, `tớ`, `tao`, `chúng tôi`, `chúng mình`, `chúng ta`, `bọn mình`, `bọn tôi`, `i`,
    `me`, `my`, `we`, `our`.
  - `BANNED_IDEAS` (R-I22, three kinds): `campaign`: `chiến dịch`, `ý tưởng quảng cáo`, `quảng cáo cảm xúc`,
    `insight cảm xúc`, `campaign`; `competitor`: `đối thủ nên`, `khuyên đối thủ`, `gợi ý cho đối thủ`,
    `lời khuyên cho đối thủ`; `trial_order`: `đơn thử`, `đặt thử`, `đặt hàng thử`, `mua thử để`.
  - `BUYING_REASON`: `lý do chọn`, `lý do mua`, `vì sao chọn`, `vì sao mua`, `tại sao chọn`, `tại sao mua`, `chọn vì`,
    `mua vì`, `quyết định mua`.
  - `RETOLD_NOTE`: `kể lại`. `SHORT_CHAIN_NOTE`: `chưa đủ bằng chứng`. `BELOW_NOTE`: `dưới ngưỡng`. `NO_DATA_NOTE`:
    `chưa có dữ liệu`.
- Gate results. A submission that breaks an input rule returns an error (`{"error", "message"}`, nothing stored).
  A well-formed submission returns `accepted` (boolean) and `reasons`, the list of every gate it fails, in the order
  of the tables below and then claim or line order. Each reason is `{"code", "claim", "detail"}`: `claim` is the

- Review text. `submit_section` and `submit_statement` read `review_text` in memory, only for `VERBATIM_QUOTE`
  (IM-Q87, IM-Q111); they store and return none of it.
- Fixed wording (revision 14, IM-Q125). The MCP's fixed wording is the closed set of strings that come from a frozen

  names; step, level and label names; part statuses; the placeholders and marks («Chưa viết», «Cần gửi lại: số liệu
  đã đổi», «Giả thuyết», «Tầng <k>»); the page headings; and the `report_plan` `unknown`, `why` and `needs` lines
  (built from fixed templates over these strings). Agent-submitted text (section text, statement fields and notes)
  is never fixed wording. The output form of the short-review rule (IM-Q81) is: no output holds a whole review of 1
  to 7 words as consecutive words outside the occurrences of fixed-wording strings. Inside them, a match is a coded

## PR 4 conventions (R-IM13 to R-IM18, change `insight-claim-layer`)

Source of truth: `openspec/changes/insight-claim-layer` (R-IM13 to R-IM18, tasks 2.1 to 2.6 and 3.1) and the decided
design of the task brief. A «claim» (ý con) is one specific thing customers say about one theme of the codebook.

- Five new tools (IM-Q126):
  - `submit_claim_catalogue(run_id, theme_code, catalogue)`.
  - `code_claims(run_id, theme_code, catalogue_version, dry_run=True, max_calls=None)`.
  - `claim_counts(run_id, theme_code, catalogue_version)`.
  - `claim_grading_packet(run_id, theme_code, catalogue_version, out_dir, seed)`.
  - `record_claim_grades(run_id, theme_code, catalogue_version, grades_dir)`.
- `theme_code` is a core or block theme code of the codebook (IM-Q24; an F310 code is not one). `catalogue_version`
  is a positive integer that the MCP gave the catalogue (IM-Q132). The catalogue's own `version` field is a free label.
- Claim store. The run warehouse holds the claim tables. They are state tables: a rebuild keeps them (like `label`).
  - `claim_catalogue(theme_code, catalogue_version, label, catalogue_json, codebook_version, submitted_at)`, primary
    key `(theme_code, catalogue_version)`, with `BEFORE UPDATE` and `BEFORE DELETE` triggers that abort.
  - `claim_coding_state(review_id, theme_code, catalogue_version, input_sha256, spec_p, rac_p, gen_p, status)`, one
    `done` row per review coded successfully under that catalogue version. `spec_p` is P(`CU_THE`), `rac_p` is
    P(`RAC`), `gen_p` is P(`CO`) of the `GEN` question.
  - `claim_label(review_id, theme_code, catalogue_version, claim_code, p_co, status)`, status `kept` or `unclear`.
  - `claim_packet(packet_id, theme_code, catalogue_version, seed, sample_id, review_id, kind)`.
  - `claim_grade(grade_id, theme_code, catalogue_version, packet_id, status, summary_json, raw_json, recorded_at)`.
  No claim table has a column that holds review text. `raw_json` holds the four grader outputs as read (IM-Q135).
- Warehouse source additions (rebuilt by every `build_warehouse`, IM-Q129, IM-Q146): the column
  `review.posted_date` (ISO date or NULL) and the table `near_dup(review_id, group_id)`, one row per review.
  A warehouse built before this PR has neither. Each of the five new tools on such a warehouse gives
  `WAREHOUSE_REBUILD_NEEDED` and no numbers. The PR 1 to PR 3 tools work on it as before.
- Customer words (R-IM14). Split the stored `review_text.text` at each run of exactly two spaces (`"  "`, the
  joiner of IM-Q33). Keep the first segment. Drop each later segment that matches `ATTRIBUTE_LINE_RE`
  `^\s*[^:]{1,40}:`. Join the kept segments that are not blank with one space. A review whose customer words are
  blank is «chỉ có dòng thuộc tính» (attribute-only).
- Shop. Shopee: the `shopId` part of the review's `product_key` (`shopee:<shopId>:<itemId>`). TikTok Shop: the
  `product_key`. Shops are worked out when counting. They are not stored.

  `CLAIM_SPECIFIC = 0.50`, `CLAIM_SPAM = 0.70`, `CLAIM_GENERIC = 0.70`, `NEAR_DUP_MIN_WORDS = 8`,
  `NEAR_DUP_JACCARD = 0.80`, `BURST_DAYS = 7`, `BURST_SHARE = 0.40`, `BURST_MIN = 5`, `ONE_PRODUCT_SHARE = 0.80`,
  `OTHER_SHARE_E15 = 0.20`, `SATURATION_SEED = 42`, `SATURATION_STEP = 25`, `SATURATION_MENTIONS = 3`, and the rules
  version `CLAIM_RULES_VERSION = "claim-2026-10-31.1"`.
- Claim count rows. One row of `claim_counts` with its `count_id` (IM-Q148). Its source is `shopee_reviews` or
  `tiktok_shop_reviews`, by its platform. Its step is `Sau mua`. It is review-derived (PR 3 conventions), and its
  theme is the catalogue's theme.
- Catalogue status: `DRAFT` or `PASSED`. A new version starts `DRAFT`. The status is the `status` of the latest
  `claim_grade` row of that theme and version, or `DRAFT` when there is none (IM-Q136).
- Grader files. `record_claim_grades` reads exactly these files in `grades_dir`: `packet.json` (written by the packet
  tool), and `r1-astra.out`, `r1-opus.out`, `r2-astra.out` and `r2-opus.out` (written by the runner). A grader file
  is read from its first `{` to its last `}` and parsed as JSON. Round 1 is
  `{grader, catalogue: [{code, verdict, note}], missing: [{name, why}], items: [{id, ok, wrong, missed, specific_ok,
  note}], dup_groups: [{group, same_idea_copy, note}], method_gaps}`. Round 2 is
  `{grader, decisions: [{n, agree_other, why}], missing_agree: [name], method_gaps_comment}`. Verdicts are `OK`,

   approval tool or UI is added (no R-IM12 work), and no record is seeded in the repo.
24. **Claim shape (IM-Q82, revised in revision 12).** R-IM10 lists a count ID, a confidence, a step and a hypothesis
   flag per claim. This table adds `ref` (the claim's marker `[^ref]`, which ties the claim to its place in the text)
   and `conclusion` (needed for the R-I33 gate). A claim may cite several count IDs, as in `confidence_ceiling`, but a
   number can only point to a claim that cites one (IM-Q84). What the prose asserts is tied to claims by the marker:
   every sentence of a data or synthesis part needs one (IM-Q108). The `conclusion` flag alone does not prove what a
   sentence says; a reader still checks meaning.
25. **Numbers (IM-Q84, revised in revision 12).** A number binds to the nearest marker (the first after it, else the
   last before it) and must carry a unit word (`đánh giá`, `người viết`, `sản phẩm`, `từ khóa`) that names the
   count field it must equal. `n/N` is allowed for a theme row's reviews over the platform's coded reviews, the one
   denominator the MCP knows to be complete (R-I06). Percentages, numbers without a unit, and number words before a
   unit are rejected, not left unchecked. Frame parts 2 and 3 may state sizes only as scope numbers of the run, each
   read with its platform and measure (collected or coded), so a size cannot be credited to the wrong platform
   (IM-Q121, revision 13); only affirmative scope forms are supported, so a number in a negated clause («chưa mã
   hóa 38 đánh giá») fails (revision 14), and so does a number whose measure or negation sits in an earlier clause,
   such as a heading before `:` (revision 15); dates and question numbers carry no unit and are not checked. Quantity words with no number («phần lớn», «đa số») are not
   caught; this is a known gap of the word lists (open question 27), not a permission.
26. **Kept motives and barriers (IM-Q113, IM-Q122, revised in revision 13).** R-I39 already decides the four kinds. The table
   maps them to the core themes `T-CONGDUNG`, `T-GIA`, `T-QUYCACH`, `T-CHATLUONG` and rejects any other theme as a
   motive or barrier, including block themes such as `T-VI`. Whether a block theme (for example taste for food)
   should count as «chất lượng» is a possible owner decision; until then it is excluded. A reason link backs a motive
   or barrier only when both its themes are kept kinds, because a line cannot show which theme the motive names
   (IM-Q122). This rejects some honest mixed-pair motives; the agent cites a direct theme row instead.
27. **Phrase lists (PR 3 conventions, revised in revision 13).** The conversion, Market, star ranking, buyer,
   first-person, banned-idea and buying-reason checks are frozen phrase lists, not meaning checks. A reworded
   prohibited claim can be missed, and an innocent sentence can be rejected (for example «doanh thu» next to a
   count); the agent then splits or rewords the sentence. Only a denial in the complete supported form passes
   (IM-Q117, IM-Q123): a listed subject, one negation, at most two link words, the phrase and no second clause.
   Other denial wordings are rejected, and affirmative forms such as «không ít» or «không chỉ» are never denials.
   Headings and missing-data sentences are exempt from `UNSUPPORTED_SENTENCE` only in their fixed forms; a
   missing-data topic comes from the closed `NO_DATA_TOPICS` table, so it cannot carry an assertion (IM-Q120,
   revision 14). These limits are disclosed, not exceptions to the approved rules.
28. **Added section codes (IM-Q92, IM-Q108 to IM-Q110).** `STEP_NOT_FROM_EVIDENCE` and `RETOLD_NOT_MARKED` enforce
   R-I31, `UNSUPPORTED_SENTENCE` enforces R-I30 and R-I20 (each conclusion and action has its evidence, level and
   step), and `BANNED_IDEA` enforces R-I22. None of them is one of the eight R-IM10 bullets; the code names are an
   engineering choice.
29. **Statement evidence (IM-Q94 to IM-Q101).** Only Shopee and TikTok Shop rows can be statement evidence, because
   the app shape has only those platforms and R-L12 takes motives and barriers from customer words. The app
   `denominator` is not filled in v1; this does not allow a report sentence to leave out a known n/N (IM-Q84).
   `replaces` is an added optional argument that gives a statement its identity across versions. The added line keys
   (`themes`, `part` on reason-link lines) stay inside `evidence`; the 9 fields stay exactly R-C01, and a null 3C is
   valid.
30. **Short reviews (IM-Q111, IM-Q125, revised in revision 14).** A whole review of 1 to 7 words copied into agent
   text is rejected, before anything is stored, so the guard matches R-IM12 «SHALL NOT chứa chữ của khách» and IM-Q81
   for every review length. The cost: a run with a one- or two-word review such as «ngon» or «rất tốt» blocks those
   words anywhere in the agent's text, and the agent must reword. Allowing common-word overlap in agent text would be
   an exception to R-IM12 and needs an owner decision; the contract does not assume one. The MCP's fixed wording
   (frozen titles, placeholders, statuses, and the coded theme labels R-I11 allows) is not customer text: a match
   inside it does not block a render and is not redacted (IM-Q125). That boundary follows R-I11, which permits coded
   labels; it is not a common-word exception for agent text.
31. **Page layout (IM-Q102).** The statements and the «chưa trả lời được» section sit between Phần 17 and the
   appendix (Phần 18). The appendix shows reason links by count and count ID only, not review IDs; a reviewer checks
   a link on the host with `find_reason_links` and `read_reviews`.
32. **Stale parts (IM-Q103).** A part written on counts that later changed is shown with its old numbers and marked
   «Cần gửi lại», not dropped and not recomputed. The wording of the mark is an engineering choice.
33. **Versions and the archive (IM-Q93, IM-Q101, IM-Q118, revised in revision 13).** A re-submit with the same

   identity depends only on report content, and an identical report reuses its stored copy (R-IM12). The latest
   versions are returned as a receipt in the render result.

   keeps `Sau mua` and must say «kể lại». A part 8 claim is always a buying reason; in other parts, the
   `BUYING_REASON` phrases mark one.

   For reason links the PR 2 ledger had no valid key, so IM-Q124 extends the PR 2 key rule with one new form bound
   to the codebook and reason rules versions. The three existing key forms are unchanged. Approvals are still recorded
   by a person through `record_method_approval`; no approval tool is added.

   both platforms together». R-I06 («SHALL NOT cộng Shopee với TikTok Shop … SHALL NOT ghi một con số gộp») and
   R-IM16 («theo từng sàn (R-I06)») forbid a combined number. The rows follow the specs: per platform only, plus the
   «có ở cả 2 sàn» marker. Saturation and «Khác» are per platform for the same reason (the pilot computed them over
   both platforms). If the owner wants a combined view, R-I06 needs an owner exception first.

   decided design has no AI call inside the MCP: the agent drafts the catalogue and sends it with
   `submit_claim_catalogue`, and the cross-check is `claim_grading_packet`, the runner and `record_claim_grades`.
   The rows follow the design. The task wording can be aligned when the change is archived.
38. **Flags that block `PASSED` (IM-Q136).** R-IM13 names chồng nghĩa, quá rộng and sai tên. The design also counts
   `QUA_HEP` and `NGOAI_CHU_DE`. The rows follow the design, which is the stricter reading.
39. **«Từ 5 lần nhắc» in the burst flag (IM-Q150).** Read as `reviews ≥ 5`, like the pilot's `measure3.py`, not as
   `max_7day ≥ 5`. Both readings satisfy the spec scenario (6 of 15).
40. **Specific and generic thresholds (IM-Q144).** «Specific» is P(`CU_THE`) ≥ 0.50, as in the pilot. A generic
   claim with 0.50 ≤ P(`GEN`) < 0.70 and no kept specific claim is stored as `unclear`, like any other claim. Both
   are engineering choices.
41. **Raw grader output (IM-Q128, IM-Q135).** The design stores both graders' raw JSON. The prompts forbid copying
   customer words, but a grader can still do it, so `claim_grade.raw_json` is treated like `review_text`: it is never
   returned and leak scans skip it. The alternative is to reject an output that holds an 8-word run of a review.

   short-review rule (IM-Q111) is not applied: a one- or two-word review such as «ngon» would block normal
   `include` text. So a claim name can equal a short review.

   lifts the draft cap of IM-Q138. The R-I32 checks still apply. The owner may prefer a non-tool writer, like

44. **Rank phrases (IM-Q158).** `CLAIM_RANK_TERMS` is a closed list and leaves out «hơn» and «nhất» alone, because
   claim names hold them (for example «xương chắc hơn»). Rewordings outside the list are not caught. Not enforced in
   sentences: a ranking sentence that cites the generic claim, and a flag word next to a flagged claim's number. Both
   are shown in `claim_counts.ranking` (IM-Q157).
45. **«Mỗi chủ đề có đủ đánh giá SHALL có một danh mục» (R-IM13).** No minimum review count is defined, so the MCP
   does not require a catalogue for any theme. The report skill decides when to draft one.
46. **Old warehouses (IM-Q130).** The claim tools need a rebuild (`WAREHOUSE_REBUILD_NEEDED`). Because `posted_date`
   is now part of `content_sha256`, the first rebuild of an old run changes its count IDs once. Old IDs stay in
   `count_registry` with their numbers (IM-Q30), and parts written on them show «Cần gửi lại» (IM-Q103).
