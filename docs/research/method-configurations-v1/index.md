# Method configuration closure v1

Status: proposed configuration packet for the 30 A40 sections. It resolves many safe descriptive procedures and identifies the exact inputs or owner choices needed for narrower claims. It is not an approved runtime policy, a readiness report for a live dataset, or evidence that a section ran.

## What this packet closes

The A40 recipes already gave every section a concrete method shape. A41 assigns candidate parameter values for literal market inventories, compatible/disjoint aggregation, owner-declared peer comparisons, dated source events, located qualitative coding, corpus-only n/N, an M10 last-observed/MAE diagnostic, I11 group records, I12 linked-unit outcomes, I16 design/result modes, and six synthesis/decision outputs. The profiles distinguish inherited A40 authority, proposed configuration, per-run input, missing evidence and genuine owner decisions.

Four dimensions stay separate for every group in [resolution-register.json](resolution-register.json):

- business review of a proposed scope is not owner approval;
- a specified method is not implemented code;
- an input requirement is not evidence that the input exists;
- implementation/readiness do not mean that the method executed or an output was reviewed.

The business-method session supplied scoped technical endorsements for the
descriptive and source-bound proposals; it did not authorize runtime use or
approve commercial interpretations. The register pins the four profile files.
The final exact-packet review disposition and eight file digests belong in the
[A41 handoff](../../handoffs/research-a41-method-configuration-closure.md), outside
this packet to avoid a self-referencing digest. Consult that receipt before
claiming final review closure. No source-file hash is claimed for the session
conversation itself.

## Authority and use

The A40 catalog supplies only canonical IDs, titles and order. The A40 authority index, recipes, accepted code/handoffs and `common-rules.md` bound the seven existing submethods and shared evidence rules. Read each profile alongside the A40 method named in its “Sources” section. A41 does not amend those contracts or claim checks the current code does not perform.

The registry is for planning and review. Its parameter classifications are not runtime enums; a `BUSINESS_REVIEWED_PROPOSAL` label does not grant permission to execute. Exact source bytes and locators, periods/timezones, denominators, membership, codebook/protocol versions and peer/group sets are run inputs when an operation needs them. A missing input blocks only the affected operation. No new customer research, experiment, provider call or synthetic respondent is needed or proposed.

Four evidence layers remain distinct: source evidence; reproducible calculation; AI interpretation; human decision. Exact citations establish pointer integrity, not semantic truth. Manual `EvidenceRecordRef` locators support located examples, not people/product/listing IDs or cross-source joins. Text repeated at different locators stays distinct. Missing is never zero. UNKNOWN remains visible. Population, causal, forecast, effectiveness, conversion, ranking and action claims remain disabled unless an exact reviewed method and authority permits them.

The optional AI candidate contract preserves AI-proposes/human-decides without executing generation. Code and driver suggestions remain unadjudicated layer-3 candidates and never enter evidence counts or synthesis by default. Owner-authored options remain separate from AI candidates. B7/B10 button-only decision contracts remain unchanged; no hidden chain-of-thought is stored.

## Suggested implementation order

1. Reuse the seven existing bounded methods without widening them: M02, M03, M04, M08/P4, M13, I03 and I17. Bind only exact artifacts accepted by their current contracts.
2. Build and review source-bound descriptive inventories that do not require a 30-section report: M05-M07 and M09; located I02/I04-I08 records; I09 same-record gap pairs; and I13 mention inventories. Keep proxy interpretation, peer membership and codebook revision explicit.
3. Add I10/I13 within-corpus counts and n/N only when corpus membership, unit and complete denominator are frozen. Exclude unadjudicated AI code suggestions. Keep population/customer claims out.
4. Implement I11 descriptive cells, I12 separated presence/exposure/outcome records and I16 gates/design-only mode after their exact boundaries are reviewed. Keep inference/effectiveness off. M10 may first report eligibility blockers; any baseline run needs explicit owner authorization and per-run splits/gaps.
5. Add M01/M11/I14/I15/M12 packets from only relevant exact claims. Consider AI candidates only after a separate implementation review of the closed schema, numeric fact bindings, retained attempt and human disposition. Never promote a candidate to an owner option or decision.

Steps describe a possible technical sequence, not approval to execute. The owner decisions in Vietnamese are grouped into four choices; ordinary input metadata should not be turned into a policy questionnaire. Root owns final source pinning, business audit integration and the A41 handoff. No tests, builds, typechecks, provider calls or runtime changes were performed for this documentation packet.
