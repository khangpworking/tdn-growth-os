# I05 · Cảm nhận và thái độ

Spec v1.0.0 · coverage `DRAFTED` · authority `PROPOSED_LOCATED_STATEMENT_METHOD` · implementation `NEW_CODE_IF_APPROVED` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

## Question and boundary

Which attitudes or feelings are explicitly stated in already available, located sources, in what context and about what? This method reports source statements. A quote or review row does not establish prevalence, sentiment of a person outside that statement, or cause.

## Inputs and procedure

Required: frozen existing-source corpus, owner question, exact `EvidenceRecordRef` per statement, surrounding context, source speaker label only as provided, date if present and source provenance. A versioned owner-approved codebook is mandatory for categorical aggregation; an exact locator is mandatory for claim eligibility. No new survey/interview is an input.

1. Freeze corpus membership and inclusion rule. Preserve the short source excerpt needed to read polarity/context plus its exact locator and digest; retain negation, uncertainty and quoted speaker attribution.
2. Assign explicit status: `positive`, `negative`, `mixed`, `neutral`, `unclear` only if these exact categories are approved in the codebook; otherwise leave unclassified. Separate target (brand/product/topic), context and direct quote. Do not infer sentiment from star rating, purchase, or silence unless a source-bound method explicitly permits it.
3. Record coder identity role, codebook version, AI suggestion if any, human adjudication and disagreement. Collapse only a repeated exact evidenceRecordRef or the same stable source record key; identical excerpt hashes at different locators remain separate.
4. Emit located examples and counts per coded evidence record. Do not calculate person prevalence or attitude share unless source supplies compatible sampling frame, distinct respondent unit, denominator and approved uncertainty method.

No hidden text extraction is a source citation. Missing is no statement located, not neutral attitude. Deterministic display order is corpus order then locator; ties remain separate.

## Output, example and limits

Output: evidence refs, quote context, explicit target, code/status, coder/adjudicator, conflicting statements, code counts by source/corpus, denominator basis and claim limits. Toy fixture: one located excerpt says “too sweet”; one says “fine after mixing”. Expected one negative concern and one mixed/positive only if approved coding supports that mapping; otherwise both stay uncoded. Two excerpts are not two customers.

Blocked fixture: sentiment summary has no exact source record/span. Expected `I05_QUOTE_LOCATOR_MISSING`; no coded claim. If source target or negation is clipped, mark unclear.

Allowed: “In this located excerpt, the speaker describes X.” Cite exact quote/span and context. Forbidden: customers generally feel X, sentiment prevalence, demographic attitudes, causal product effect or owner recommendation.

AI role: may suggest a code on exact excerpt, never create source text or counts; human adjudicates and records disposition. Required inputs are the located statement and context; I02 context and M13 provenance are optional reusable outputs. Open choices: codebook, corpus/sampling frame, coding unit, coder agreement/adjudication, duplicate policy, prevalence/uncertainty method. Proposed blockers: `I05_CORPUS_UNFROZEN`, `I05_QUOTE_LOCATOR_MISSING`, `I05_CODEBOOK_UNAPPROVED`, `I05_DENOMINATOR_UNSUPPORTED`. Reopen on corpus/codebook/context changes. Acceptance: quote without locator is ineligible; no population percentage from record counts; code disagreements remain visible.

Record identity: apply the common-rules record-identity policy. Collapse only repeated exact evidenceRecordRef values or records proven identical by a stable source key. Identical wording at different row/span locators remains distinct; text hashes alone never authorize record deduplication. Corpus counts are coded records, not people.
