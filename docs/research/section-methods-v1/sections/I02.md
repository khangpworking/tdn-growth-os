# I02 · Khách hàng và hoàn cảnh

> **Current authority (2026-10-08):** Superseded by [Ultimate v1.12](../../ultimate-method/ultimate-method-30-sections.md) where they differ: E4 permits evidence-backed synthesized personas; E11 defines coding defaults, with L2/L3 labels and identity limits. The historical D06 blanket persona prohibition below is not the current rule. Persona implementation and cross-check release eligibility require their own evidence.

Spec v1.0.0 · coverage `DRAFTED` · authority `PROPOSED_LOCATED_CASE_METHOD` · implementation `NEW_CODE_IF_APPROVED` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

## Question and boundary

What contexts are directly described in existing, located research or customer-facing records? This method describes evidence records, not customer segments, population distributions or personas. No new survey/interview/recruitment is proposed.

## Inputs and procedure

Required: owner question and scope; frozen corpus manifest of already held/published sources; each item as `EvidenceRecordRef` with exact package digest, file/version, row/span/quote locator, available time metadata, declared context fields and provenance; owner-approved context codebook if classifying. `CaseRef.caseId` or `episodeId` is optional and may be used only when source-issued. Internal evidence locators do not identify people.

1. Freeze exact source digests and eligible record list before coding. Partition by source, period, geography and source population; incompatible frames stay separate.
2. For each record, extract only explicit context attributes: source-stated role/situation, task, time and setting. Store exact source wording and locator. Map to a code only when an approved codebook is supplied; otherwise retain source wording as uncoded context. Unknown, absent and conflicting values remain separate.
3. Collapse only a repeated exact `EvidenceRecordRef` or repeated source-issued same-record key. Identical text at distinct locators stays as two records. Without source-issued person identity, count located records, not unique customers; no cross-source joining or cohort membership.
4. Output context records, coding/adjudication status, source coverage and counterevidence. No percentages unless a compatible explicit denominator and approved sampling design support the target population claim.

Missing field means `UNKNOWN`, not inferred. Stable display order is source digest, file path, locator. No ranking, cluster, persona generation or prevalence model is authorized.

## Output, example and limits

Proposed output fields: evidenceRecordRef, context fields and their direct/unknown status, codebook version, coder/adjudicator/provenance, conflict refs, record count and claim limits. Toy fixture: two synthetic source excerpts state “shopping before a trip” and “caregiver purchase”; output two located context examples. It does not assert two people or segment proportions.

Blocked fixture: a summary says “young parents usually buy” but has no retrievable source locator. Expected `I02_NO_LOCATED_EVIDENCE`; statement is not claim-eligible. If context is supplied only by model, label as unverified interpretation, not evidence.

Allowed: “These two located sources describe contexts A and B.” Cite exact source/span. Forbidden: customer counts, population persona/prevalence, universal needs, causal context or demographic identity not stated by source.

AI role: may propose codebook matches only after approved taxonomy, with quote locator; human coder/adjudicator decides. No generated customer answer enters evidence. Dependencies: M02 scope, M13 provenance when available; no M01 dependency. Open choices: context taxonomy, record eligibility, coding/adjudication and any sampling frame. Proposed blockers: `I02_CORPUS_UNFROZEN`, `I02_NO_LOCATED_EVIDENCE`, `I02_CODEBOOK_UNAPPROVED`, `I02_POPULATION_DENOMINATOR_ABSENT`. Reopen on source/corpus/codebook change. Acceptance: located examples remain record-level (future output boundary); no person count without IDs; unlocated claim blocked. No runtime implementation exists.
