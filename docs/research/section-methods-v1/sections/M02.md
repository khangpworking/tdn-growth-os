# M02 · Phạm vi và phương pháp

Spec v1.0.0 · coverage `DRAFTED` · authority `EXISTING_BOUNDED_SUBMETHOD` · implementation `EXISTS_A22` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

## Question and boundary

What exact normalized Metric scope, source membership, observation coverage, label state and period basis feed this report? The executable submethod is A22's deterministic scope/method account. It does not decide whether the selection represents a market, define a new market boundary, validate source truth, or write a methodology conclusion. Broader scope adequacy is an owner review.

## Inputs

| Required field | Type / source | Check |
|---|---|---|
| `input` | Exact normalized Metric input: profile/codebook versions, scope `{key, platform, selection, start, end, acquiredAt?, periodBasis, currency}`, sources and records | Schema-valid; `start <= end`; each record uses exactly the same measurement profile/scope/period/currency; no duplicate `[shopId, listingId]`; source refs resolve to declared source digests. |
| `result` | Exact `metric-scope-v1` result for `input` | Canonical result input equals the supplied normalized input; frozen label policy and label issues replay. |
| `selectedSources` | 2–3 source metadata records selected by the surrounding source-package reader | Distinct source digests; selected roles/paths were checked against the finalized package by that reader. |
| `rawByteMappings` | One mapping per selected source: role, logical path, package digest, raw digest, bytes, media type, export path | Same order and metadata as sources. The surrounding verified package reader checks raw bytes; the A22 builder checks mapping metadata consistency. |

No extra file is optional inside this existing method; absent source mapping blocks the artifact. `acquiredAt` may be null when not declared. No date is inferred from a filename, modification time or report period.

## Compatibility and procedure

1. The surrounding source-package reader replays the selected package/files and A30/A1 pipeline verifies normalized source bindings. This method itself does not authenticate the provider or decide whether the declared period is suitable.
2. Assert result.input equals input. Require 2–3 selected-source/mapping pairs. Reject a mismatch between metadata pairs, an unknown or duplicate selected digest, or any record locator whose source digest is outside the selected set.
3. Emit `scope` as supplied plus VND. Set `measurement.recordCount = records.length`. Count, separately for revenue and units, each state (`missing`, `observed_zero`, `observed_value`), each precision (`exact`, `display_rounded`, `estimated`, `unknown`), and nonempty locator. Count labels by classification and adjudication state; retain `labelIssueCount`.
4. Copy exact file identity/period/provenance and raw-byte mapping. Canonicalize payload; compute `methodOutputId = SHA256(canonical JSON payload)`; validate and retain the exact artifact.

Dedup unit is `[platform, shopId, listingId]` per normalized input, with the implementation's canonical pair validation. Counts use integer record totals. There is no inferred population denominator: `recordCount` is the selected observation-row denominator only. Missing and zero counts remain separate; no percentage is produced by M02. The implementation's canonical input order is preserved; ties are irrelevant.

## Output, example and failure

Output `m02-scope-method.json`: `scope`, `measurement` (profile/codebook/WIDE UNKNOWN policy, record/locator/label counts and revenue/unit coverage), selected `sources`, `rawByteMappings`, source-verification state, limitations and content ID.

Synthetic example: 3 valid rows; revenue states are observed 10, observed zero, missing; all 3 unit values are observed; all 3 required record locators resolve; one label is UNKNOWN. Expected M02 counts: revenue `observedValue=1`, `observedZero=1`, `missing=1`; units `missing=0`; record count `3`; record locator count `3`; no market total or percentage is inferred.

Blocked example: the third row references digest `h3`, absent from the selected package files. Expected blocker `M02_SOURCE_REF_NOT_SELECTED`; no artifact is emitted. A period string incompatible with the declared manifest convention also blocks rather than being normalized by guessing.

## Claims, review and dependencies

Allowed: “This draft used N normalized rows from these exact package files; X rows had a located record reference; the declared period/profile was …”. Link each statement to exact JSON pointers and file digest. Forbidden: “N represents the market”, provider-verified, complete, representative, true, growth, demand or causal claims.

AI role: none. Human owner checks scope adequacy, period meaning, source selection and intended report use; OWNER review remains required. Depends on A30 preparation, A31 exact readiness/catalog and the exact source package; useful downstream to M13, I03 and I17. It does not depend on M01. Proposed blockers: `M02_PREPARATION_MISMATCH`, `M02_SOURCE_MEMBERSHIP_MISMATCH`, `M02_RAW_MAPPING_MISMATCH`, `M02_SCOPE_PERIOD_INVALID`.

Reopen on package/mapping/period/profile/label-policy/locator changes or failed replay. New scope adequacy or market definition is an owner decision, not a code default. Acceptance scenarios: (a) absent and observed-zero counts remain 1 each (A22 method builder owns); (b) a changed source byte digest rejects output (source-package replay owns); (c) no row-count-to-market claim is emitted (method contract/OWNER review owns). Existing source/package tests cover byte replay; do not duplicate them here.
