# M09 · Động lực và rủi ro

Spec v1.0.0 · coverage `DRAFTED` · authority `PROPOSED_SOURCE_BOUND_EVENT_INVENTORY` · implementation `NEW_CODE_IF_APPROVED` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

## Question and boundary

Which dated source statements describe a possible market driver or risk, what exact scope do they name, and what evidence supports or contradicts each statement? The safe first procedure is an event/risk evidence inventory. Temporal coincidence does not establish causality, probability, impact or forecast.

## Inputs

| Required | Typed fields and checks |
|---|---|
| Owner question and target scope | `{targetMetricOrDecision, entityOrGeographyRefs, period, reasonForInclusion}`. Exact IDs or source-local references only. |
| Existing dated evidence | `SourceFileRef`, exact quote/row locator, publication/event/observation date with date meaning, source-reported entity, event statement and provenance. |
| Optional counterevidence | Same event/scope or a directly conflicting source; exact locator and date. |
| Optional classification codebook | Versioned owner-approved event/risk classes; absent codebook means retain source wording and no class assignment. |

## Procedure and compatibility

1. Freeze owner target and exact source corpus. Separate source publication date from claimed event date and from metric observation period. If one is not stated, output null/unknown.
2. For each located source statement, extract only source-explicit event, date, target entity/geography and stated direction. A stable identity link must come from source or owner input; lexical similarity alone cannot resolve entities.
3. Attach one or more source links and counterevidence. Use an approved codebook if supplied; otherwise label as uncoded evidence. Keep `documented_event` separate from `candidate_driver_hypothesis`. A hypothesis may be proposed for human review only when its mechanism and affected metric are separately stated; do not produce causal wording or probability.
4. Order rows by known event date then exact source digest/locator; undated entries follow in stable source order and remain undated. Never compute a trend/effect window unless an approved compatible measure and window exist. If quantifying, require matching units/period, direct source value and nonzero compatible denominator.

Dedup same source event only by stable source key or exact duplicate digest; no fuzzy cross-source dedup. Conflicting sources remain separate. Missing date is not zero/no event. No numerical risk score, likelihood/impact scale, event weighting or aggregate driver rank is defaulted.

## Output, example and failure

Proposed output: target scope; exact source/event locator; source date, event date and date basis; entity link and basis; codebook class or uncoded; directly reported direction; support/counterevidence refs; hypothesis state; compatibility and limits.

Toy fixture: one existing dated report states a policy change occurred on date D; another located source disputes its effective date. Expected two source records, one conflict, and no measured causal effect. Date D is toy data.

Blocked fixture: text similarity suggests an event may concern a marketplace entity but provides no stable link to target scope. Expected `M09_ENTITY_LINK_UNRESOLVED`; keep it as unrelated source note, no driver claim.

## Claims, ownership and open choices

Allowed: “Source S reports event E on date D; source T reports a different date.” A human-reviewed hypothesis must be labeled as such and cite its mechanism and limits. Forbidden: this event caused growth/drop, probability or impact score, forecast, confident risk ranking, or general market driver from timing alone.

AI role: may propose candidate source-bound classifications only after an approved codebook; deterministic code validates schema/locators; human adjudicates before use. No model-generated evidence or causal statement is accepted. Depends on M02 scope/M13 provenance; downstream M01 gets reviewed claims only.

Open parameters: driver/risk taxonomy, relevant entity/link basis, eligible source types, date hierarchy, effect windows, impact/likelihood scale and adjudication. Proposed blockers: `M09_TARGET_SCOPE_REQUIRED`, `M09_EVENT_DATE_UNKNOWN`, `M09_ENTITY_LINK_UNRESOLVED`, `M09_COUNTEREVIDENCE_CONFLICT`. Reopen on source, date, link or codebook change. Acceptance: conflicting dates stay explicit (future output owner); unknown date stays null; co-occurrence never yields causality without separately approved design.
