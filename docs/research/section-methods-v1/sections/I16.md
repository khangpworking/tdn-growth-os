# I16 · Thử nghiệm và đo lường

Spec v1.0.0 · coverage `DRAFTED` · authority `PROPOSED_EXISTING_RESULT_OR_DESIGN_ONLY` · implementation `NO_APPROVED_ANALYSIS_METHOD` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

## Question and boundary

What outcome was measured under an existing experiment, or what measurement design was specified but not executed? Keep design-only material distinct from actual assigned/exposed data and results. This recipe does not request or perform new recruitment, survey, user testing or experiment execution.

## Inputs and procedure

Two exclusive input modes:

| Mode | Required fields |
|---|---|
| `EXISTING_RESULT` | Exact existing protocol/version; assignment mechanism and unit; treatment/comparator; eligibility/exposure instrumentation; outcome definition, unit, observation window; exact outcome data and source locators; exclusions/attrition; predeclared estimator, missing-data and uncertainty method. |
| `DESIGN_ONLY` | Owner question; outcome and unit; comparator; assignment plan; instrumentation and data source; analysis window; planned exclusions and owner-supplied decision/uncertainty rule or explicit `UNSET`. No execution evidence or results. |

1. Validate mode and required fields. A design-only record returns `METHOD_ONLY`, `NOT_EXECUTED`, and null result values; do not move it into result mode without exact existing execution evidence.
2. For existing results, freeze exact protocol and analysis plan before reading outcome values. Verify assignment, outcome, unit, comparator, exposure, timeframe and data membership all align. If any required field is absent/incompatible, no lift calculation.
3. Execute only the estimator named in the retained approved plan. For example, binary outcome risk difference can be `treated successes / treated assigned units − comparator successes / comparator assigned units`; its use, missing-data handling, uncertainty method and denominator must be explicitly selected before analysis. Retain raw counts, exact denominators, estimate, uncertainty and limitations. Do not choose the estimator after seeing results.
4. Report executed output separately from design fields. An existing experiment's randomized assignment may support a causal interpretation only when design integrity and approved analysis are reviewed; observational exposure does not.

Missing outcomes stay distinct from non-events. `0` is a measured outcome only if instrumented and observed. No duplicate participants/events without stable assignment-unit IDs. No lift threshold or success cutoff is provided.

## Output, example and limits

Output: mode/status, exact protocol, unit, comparator, outcome, assignment/exposure, instrumentation, period, exclusions, estimate/uncertainty or null, source pointers, missingness, review disposition and blockers. Toy result fixture: predeclared binary estimator, 4/10 treatment and 3/10 comparator successes; expected risk difference `0.40−0.30=0.10` before any uncertainty assessment. This is arithmetic only, not executed evidence.

Blocked fixture: a design document names treatment but lacks comparator or outcome instrumentation. Expected `I16_DESIGN_INCOMPLETE`, `NOT_EXECUTED`, no estimate.

Allowed: design-only intent, or reviewed estimate tied to an exact existing protocol/data. Forbidden: claim of experiment/lift from design alone; causal effectiveness from unassigned exposure; new participant collection; post-hoc outcome/threshold choice.

AI role: none for assignment, estimator, threshold or numeric result. Human owner approves design and interpretation; execution/results require existing evidence and a review disposition. Requires existing protocol, assignment/instrumentation and outcome data directly, NOT an I12 section artifact. M13 provenance may be reused optionally. Only an explicit human-reviewed result disposition permits downstream M11/I14 decision-support use; exact protocol/data digests alone do not approve it. Open choices: estimand, assignment unit, outcome window, exclusions, missing rule, uncertainty method, success threshold and review. Blockers: `I16_MODE_UNDECLARED`, `I16_PROTOCOL_MISSING`, `I16_OUTCOME_OR_UNIT_MISSING`, `I16_COMPARATOR_MISSING`, `I16_ASSIGNMENT_MISSING`, `I16_INSTRUMENTATION_MISSING`. Acceptance: design-only result stays null/unexecuted; missing outcome is not zero; no lift without assignment, comparator, instrumented outcome and approved analysis.
