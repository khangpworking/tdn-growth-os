# I10 · Chủ đề và mối quan tâm

Spec v1.0.0 · coverage `DRAFTED` · authority `PROPOSED_FROZEN_CORPUS_CODING` · implementation `NEW_CODE_IF_APPROVED` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

## Question and boundary

Which themes appear in one frozen, already available corpus, under an owner-defined codebook and sampling frame? This proposal reports coded evidence records. It does not claim population prevalence from a review/search sample or treat text co-occurrence as causality.

## Inputs and procedure

Required: question; corpus manifest/digest; source item per record with `EvidenceRecordRef`, date, channel/type and exact content span; documented frame and inclusion/exclusion rules; versioned codebook; coder/adjudication provenance. Optional source-issued item IDs may support within-source dedup. No new collection or synthetic respondents.

1. Freeze the corpus and sampling frame before coding. Record how records entered the corpus; if frame/selection is unknown, only a source inventory is allowed.
2. Split content into approved coding units (post, review, article section or exact passage) according to the owner policy. Each unit retains its source locator and content digest. Assign one or more themes only if codebook says multi-code is valid; otherwise adjudicate overlaps.
3. Two coders/adjudicator roles are recorded only when actually present; do not claim reliability from one unreviewed coding pass. Preserve disagreements and uncodable text. Deduplicate only repeated exact evidenceRecordRef values or a real stable source record key, never text-content hashes alone; no fuzzy cross-source dedup or people count without stable IDs.
4. Output coded-unit count and code frequencies within the frozen corpus only. Prevalence requires a population-relevant probability sampling design, respondent denominator, dedup policy and predeclared uncertainty method; absent any, suppress population wording/rates.

Unknown code is not no theme. Missing/unreadable content stays in denominator only if the approved frame says so; otherwise identify exclusions. No top-theme ranking until a tie policy and appropriate count basis are approved; default display uses codebook order.

## Output, example and limits

Output: frame and digest, unit definition, exact content locator, theme codes, coding/adjudication history, frequency denominator, excluded/unknown count, counterevidence and claim limits. Toy fixture: frozen set of five synthetic text records; approved code “packaging” matches two records and “taste” one. Output 2/5 and 1/5 corpus-record counts, not user prevalence.

Blocked fixture: a 20-row sample lacks source IDs and selection frame. Expected `I10_FRAME_OR_IDENTITY_INCOMPLETE`; show located records only, no deduplicated theme prevalence.

Allowed: “Theme T was coded in 2 of 5 retained records under codebook C.” Forbidden: “40% of customers”, trending/theme growth, causal relation or unmet demand from topic frequency.

AI role: optional coding suggestion with quote pointer, model/prompt version and validation; human adjudication required before a coded claim. AI cannot generate corpus or executable coding. Requires its frozen corpus/codebook directly. I02/I05 context and M13 provenance may be reused optionally. No dependency on I13: I13 may consume this coding output, not the reverse. Open choices: frame, unit, codebook, multi-code, dedup, coder/adjudication and prevalence design. Blockers: `I10_CORPUS_UNFROZEN`, `I10_SOURCE_LOCATOR_MISSING`, `I10_CODEBOOK_UNAPPROVED`, `I10_PREVALENCE_FRAME_MISSING`. Reopen on corpus/frame/codebook changes. Acceptance: same codebook produces a fixed record count; unframed samples do not claim prevalence; duplicate policy never fabricates identities.

Record identity: apply the common-rules record-identity policy. Collapse only repeated exact evidenceRecordRef values or records proven identical by a stable source key. Identical wording at different row/span locators remains distinct; text hashes alone never authorize record deduplication. Corpus counts are coded records, not people.
