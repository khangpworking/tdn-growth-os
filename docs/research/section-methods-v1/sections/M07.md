# M07 · Đối thủ

Spec v1.0.0 · coverage `DRAFTED` · authority `PROPOSED_COMPARISON_METHOD` · implementation `NEW_CODE_IF_APPROVED` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

## Question and boundary

What comparable, source-located observations exist for the owner-defined peer set? This is a comparison table, not an automatic competitor classifier, winner ranking or strategic score. A product/shop is not an opponent merely because it appears in the same search or category.

## Inputs

| Required | Typed fields and checks |
|---|---|
| Owner peer-set declaration | `{anchorEntityRef, peerEntityRefs[], relationshipBasis, scope, inclusion/exclusionVersion}` using only source-issued IDs or exact internal evidence refs. |
| Existing observations | `SourceFileRef` + exact locator; entity as source identifies it; measure, value/state, unit, price state if price, period/timezone, variant/pack/version and provenance. |
| Optional comparison measure policy | Exact measure and permitted transformation; source records must use same definition and unit. |
| Optional baseline | Exact anchor value/source in the same compatible period; without it, show parallel observations only. |

## Procedure and compatibility

1. Freeze peer membership and basis before reading values. If no approved universe exists, output an unranked inventory of candidate references, not a competitor set. Do not use AI to add peers.
2. Partition observations by measure, unit, period and timezone, source population, entity/variant, selection and price state. Keep mismatched groups in separate rows. Do not cross-link manual rows unless an actual shared source identity exists.
3. For a compatible peer and anchor, report the exact raw values side by side. If a selected deterministic difference is authorized, calculate `peer − anchor`; a ratio additionally requires nonzero anchor and approved ratio interpretation. Preserve missing/zero/non-exact states and exact pointers. Do not normalize package price per unit unless an approved method provides the denominator; M08/P4 alone is one quote and does not authorize comparison.
4. Sort by owner-declared peer order. If none exists, sort exact references lexically for stable display and label order non-prioritized. Emit conflicts and unavailable comparisons, not an aggregate “best” score.

Dedup requires source IDs; otherwise duplicate-looking records remain separate located evidence. No arbitrary tie breaking, weight, common scale or ranking. Compare only same common period/universe and measurement; without, retain separate cells.

## Output, example and failure

Proposed output fields: peer-set version and basis, entities/references, source/value/unit/state/period, compatibility partition, optional exact delta, conflicts, status, limitations and blockers.

Toy fixture: owner selects two synthetic peer refs; anchor value 10 units and peer value 12 units from same declared compatible measure/period. Expected side-by-side values and optional arithmetic delta +2 only if that difference operation is approved. No rank follows from +2.

Blocked fixture: peer is a listing row and anchor is a different variant/pack or period, with no equivalence rule. Expected `M07_UNIVERSE_OR_MEASURE_INCOMPATIBLE`; no numeric comparison. If peer set is absent, inventory stays unranked.

## Claims, ownership and open choices

Allowed: “For the owner-specified peer set and comparable measure/period, the sources report …”. Cite each file, locator, unit and period. Forbidden: best/worst, market rank/share, product equivalence, strategic advantage, price leader or causal explanation without explicit approved definitions/evidence.

AI role: none for peer discovery, entity resolution, comparison math or ranking. Human owner defines the peer set, anchor, dimensions and meaning. Depends on M02 scope and M13 lineage; M08 quote may be a separately labeled input but cannot be compared without an approved broader method.

Open parameters: peer universe, entity/variant rules, relationship basis, common period, measure definitions, allowed transformations, rank/weight policy and conflict resolution. Proposed blockers: `M07_PEER_SET_UNAPPROVED`, `M07_IDENTITY_UNRESOLVED`, `M07_PERIOD_INCOMPATIBLE`, `M07_MEASURE_INCOMPATIBLE`. Reopen on peer membership, source or basis change. Acceptance: mismatched periods do not compare (future validator); unapproved list is not ranked (human authority); all deltas preserve exact units (comparison boundary).
