# I09 · Nhu cầu chưa được đáp ứng

Spec v1.0.0 · coverage `DRAFTED` · authority `PROPOSED_LOCATED_GAP_METHOD` · implementation `NEW_CODE_IF_APPROVED` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

## Question and boundary

Which existing located records explicitly describe a desired outcome that the source says was not achieved, and in what context? Absence from a sample, an unanswered web search, low sales or a complaint alone does not establish unmet demand.

## Inputs and procedure

Required: owner question; frozen, already available source corpus; `EvidenceRecordRef` with exact row/span/quote locator and provenance; explicit source-stated desired outcome/need; explicit current state or failed attempt showing a gap; context and available next action. Codebook is required for grouping. No new customer research is proposed.

1. Freeze eligible source membership and coding policy before reading results. Keep question/desired state and observed current state as separate fields with locators.
2. Classify a located item `explicit_gap` only when the same record directly states both the desired outcome and that current state did not meet it. If either field is absent, use `incomplete_evidence`; do not infer from silence or catalog absence. A workaround is retained only when source states it.
3. Code gap type only against approved codebook; preserve coder, adjudication and counterexamples. Deduplicate only repeated exact evidenceRecordRef values or the same real stable source record key; identical text at different locators stays distinct. Without stable person identity, units are evidence records, not unique customers.
4. Emit located examples and record counts. A rate or prevalence needs owner-approved sampling frame, person/respondent unit, compatible denominator and uncertainty rule; otherwise no rate.

Missing desired outcome, current state or locator blocks claim eligibility. UNKNOWN is separate from explicit no gap. Sort by exact source digest/locator. No gap size, severity or opportunity rank is calculated.

## Output, example and limits

Output: evidence ref, desired outcome, current result, gap status, context, explicit workaround, codebook/adjudication, counterevidence, record denominator/coverage and limits. Toy fixture: one existing support record explicitly says a user sought a tablet form and could not find it at a named retailer. Expected one located gap example, no count of users or market unmet demand.

Blocked fixture: the product is absent from a sampled category export, but no source states a need. Expected `I09_SAMPLE_ABSENCE_NOT_GAP`; no unmet-need claim.

Allowed: “This source records an explicit gap G in context C.” Cite exact spans. Forbidden: latent demand, prevalence, market opportunity size, common unmet need, reason/cause or action priority.

AI role: may suggest codebook mapping only on exact excerpt and approved codebook; human adjudicates. Source context and statements are required inputs; I02/I05/M13 are optional reusable outputs. Open choices: gap criteria, coding taxonomy, corpus/sampling frame, person denominator, severity/priority. Blockers: `I09_DESIRED_STATE_MISSING`, `I09_CURRENT_GAP_MISSING`, `I09_NO_LOCATED_EVIDENCE`, `I09_PREVALENCE_UNSUPPORTED`. Reopen on corpus/codebook/context change. Acceptance: sample absence never becomes unmet need; incomplete statement remains incomplete; record examples remain separate from people prevalence.

Record identity: apply the common-rules record-identity policy. Collapse only repeated exact evidenceRecordRef values or records proven identical by a stable source key. Identical wording at different row/span locators remains distinct; text hashes alone never authorize record deduplication. Corpus counts are coded records, not people.
