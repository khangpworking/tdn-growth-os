# I06 · Hành trình

Spec v1.0.0 · coverage `DRAFTED` · authority `PROPOSED_LINKED_EPISODE_METHOD` · implementation `NEW_CODE_IF_APPROVED` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

## Question and boundary

What order does an existing source actually record? Distinguish a record-local self-reported sequence from linked instrumented events. Cross-record assembly requires real source-issued episode links; a same-record narrative may state an order without establishing an independently observed customer journey. No new customer tracking or research collection is proposed.

## Inputs and procedure

Required for an event inventory: owner scope, exact corpus digest, `EvidenceRecordRef`, source-stated touchpoint/action, context, available timestamp and provenance. Required for cross-record episode assembly: source-issued episode ID linking events, event IDs/order and compatible time precision. Any outcome linkage needs actual compatible source keys. A record-local narrative instead requires explicit before/after relations within that same located record; no identity is inferred. Owner codebook is required for touchpoint categories.

1. Freeze the existing corpus and source identities. Parse each event only from its exact row/span. Represent absent time as unknown; do not infer sequence from section order or file modification time.
2. For cross-record events, group only by an actual stable episode key supplied by the source; order by source time and explicit sequence, otherwise mark unresolved. For a single source account, retain explicit before/after relations between its exact spans with `sequenceBasis=SOURCE_EXPLICIT_SAME_RECORD`, `identityScope=RECORD_LOCAL`, `sequenceState=SOURCE_STATED_ORDER`. Do not invent event times or episode/person IDs. A list without explicit ordering remains unresolved. No fuzzy matching or manual cross-file person joins.
3. Map touchpoints to owner-approved codebook; retain raw label and adjudication. Show missing steps as “not observed in this source”, not as a skipped customer step. A measured outcome must link to same episode and compatible timeframe under an approved rule.
4. Output each source-linked episode or record-local account separately and label its basis. Record-local narrative output cannot feed journey aggregation, conversion, drop-off or outcome linkage. Any comparable cross-record aggregation needs actual episode/event keys and an approved denominator; it still does not count people without person identity or establish prevalence without a sampling frame.

Tie rule: exact source order only if source provides it; otherwise equal/unknown times retain source record order for display but `sequenceState=UNRESOLVED`. Missing/observed-zero semantics apply to outcome measures; no outcomes inferred.

## Output, example and limits

Output: episode ref or null, events, source locators, timestamp/sequence basis, touchpoint code, linked outcome refs, missing steps, adjudication, denominator/coverage and limits. Toy fixture: one synthetic source log has episode E and events A at 09:00, B at 10:00; expected A→B within that record only.

Blocked fixture: two manually written documents name the same first name but contain no shared episode key. Expected `I06_STABLE_EPISODE_LINK_MISSING`; report both as unlinked events, no joined journey.

Allowed with source keys: “Source S records two ordered events in episode E.” Allowed for record-local narrative: “This source account states that A preceded B in this record.” Forbidden: treating narrative order as instrumented observation or a validated customer journey; typical path, drop-off, people/cohort/prevalence claims, channel causality or conversion from that account.

AI role: none for linking/ordering. It may propose codes only under an approved codebook and exact locator; human adjudicates. Required inputs are located source events and their explicit ordering/linkage. I02, I04 and M13 are optional reusable outputs, not mandatory section completions. Open choices: touchpoint taxonomy, timestamp tie policy, identity/episode source, outcome window, sample frame. Blockers: `I06_EPISODE_ID_MISSING`, `I06_EVENT_ORDER_UNRESOLVED`, `I06_OUTCOME_LINK_MISSING`, `I06_CODEBOOK_UNAPPROVED`. Reopen on source/link/codebook changes. Acceptance: no cross-file fuzzy joins; unknown order stays explicit; outcomes are not inferred.

Record identity: apply the common-rules record-identity policy. Collapse only repeated exact evidenceRecordRef values or records proven identical by a stable source key. Identical wording at different row/span locators remains distinct; text hashes alone never authorize record deduplication. Corpus counts are coded records, not people.

Record-local toy example: one located account explicitly states “first A, then
B.” Retain its two span pointers and the source-stated A-before-B relation;
person/episode ID and timestamps remain absent. A different account merely
listing “A, B” returns UNRESOLVED order. Neither yields conversion or a verified
journey. These are synthetic method illustrations, not simulated respondents.
