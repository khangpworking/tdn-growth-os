# I04 · Hành vi

Spec v1.0.0 · coverage `DRAFTED` · authority `PROPOSED_SOURCE_BOUND_BEHAVIOR_CODING` · implementation `NEW_CODE_IF_APPROVED` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

## Question and boundary

What actions are directly recorded in existing evidence, and when does a stable source record link those actions into an episode? Behavior codes describe recorded actions; they do not reveal intention or cause. No new participant collection is proposed.

## Inputs and procedure

Mandatory: exact existing source corpus, owner question, `EvidenceRecordRef` for each located event, source-stated action and available event time/context. An approved action codebook is required for categorical counts. Optional `caseId`/`episodeId` and event sequence IDs must be source-issued, not generated from name or wording. Outcome record and stable link are required for any action-to-outcome analysis.

1. Freeze corpus and codebook. Retain each observed event with raw span, locator, timestamp precision and source wording. Distinguish explicit `no action` from missing event logging.
2. If a source-issued episode key links events, sort by known timestamp then explicit source order; unresolved temporal ties remain unresolved, not inferred from an ID. Without episode keys, events remain unlinked across records. Within one located account only, explicit before/after wording may support the separately labeled record-local source-stated sequence defined in I06; it is not independently observed order or an outcome link. Never join manual records by similar names/text.
3. Code action using the approved codebook and record coder/adjudication. Keep disagreements and counterexamples. Counts are evidence-record or event counts only unless distinct people and sampling denominator are established by source.
4. Compare action/outcome only when the same stable episode has compatible timestamps, outcome definition and exposure window supplied by approved policy. Report observed sequence, not causality. Otherwise emit no outcome relationship.

Compatibility requires same source action definitions, scope, period convention, and codebook. Missing event/outcome stays null; zero requires explicit logged zero. No ranking or inferred motive.

## Output, example and limits

Output: event locator, exact action text/code, time and sequence state, optional episode link, outcome ref/status, coder/adjudication, counterevidence and blockers. Toy fixture: an existing record contains three timestamped steps with the same source-issued episode ID; expected ordered sequence of three events. This does not show common behavior among customers.

Blocked fixture: a narrative mentions “clicked” in one file and “bought” in another, with no stable episode/person key. Expected `I04_EPISODE_LINK_MISSING`; two separate examples, no conversion rate or causal claim.

Allowed: “This source records action X followed by Y in one linked episode.” Forbidden: people counts without identity; intent; population journey frequency; action caused purchase; causality from sequence alone.

AI role: candidate code suggestion only with quote/event pointer and approved codebook; human adjudication required. Requires located event/context input directly; may reuse I02 context and M13 source locators where present, without requiring those section outputs. Open choices: action codebook, timestamp tie handling, event identity, outcome linkage and eligible denominator. Proposed blockers: `I04_EVENT_LOCATOR_MISSING`, `I04_EPISODE_LINK_MISSING`, `I04_OUTCOME_INCOMPATIBLE`, `I04_CODEBOOK_UNAPPROVED`. Reopen on evidence/codebook/link changes. Acceptance: unlinked events never form a journey; timestamp ambiguity is visible; no conversion rate without linked outcomes/denominator.

Record identity: apply the common-rules record-identity policy. Collapse only repeated exact evidenceRecordRef values or records proven identical by a stable source key. Identical wording at different row/span locators remains distinct; text hashes alone never authorize record deduplication. Corpus counts are coded records, not people.
