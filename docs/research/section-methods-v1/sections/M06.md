# M06 · Nguồn cung

Spec v1.0.0 · coverage `DRAFTED` · authority `PROPOSED_OBSERVATIONAL_METHOD` · implementation `NEW_CODE_IF_APPROVED` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

## Question and boundary

What supply-related records already exist for the declared scope, and what do they directly report about offered or available quantity? Offer rows, import entries, product listings and capacity statements are different measures. This proposal does not infer unique products, current availability, market capacity or source completeness from a row count.

## Inputs

| Required | Typed fields and checks |
|---|---|
| Owner supply definition | `{supplyObject, unit, scope, inclusionRule, observationMeaning}`; define whether the target is offers, units, capacity, production, imports or another exact measure. |
| Existing supply observations | `SourceFileRef`, exact locator, source time/period, entity as represented by source, measure/unit, observed state/value, availability/capacity wording and provenance. |
| Stable identity, when available | Source-issued product/offer/entity key plus variant/version dimensions. If absent, retain an internal `EvidenceRecordRef`; do not invent IDs. |
| Optional eligible-universe denominator | Exact compatible inventory/universe count and source, period and inclusion rule; without it, report only raw observations. |

## Procedure and compatibility

1. Freeze source package and owner definition. Preserve source wording separately from normalized fields. A source's “in stock” statement is `sourceReportedAvailability`, not independently verified supply.
2. Partition records by supply object, unit, source period, geography, variant and status. Do not convert offer count to unit capacity or mix imports, listings and capacity. A count of unique offers is allowed only when a stable source identity and dedup rule are supplied; otherwise output located record count.
3. Sum measured quantities only inside an identical compatible unit/period and additive frame. Keep `missing`, explicit zero and observed positive quantity distinct. A percentage requires an owner-declared eligible-universe denominator with identical scope/period/unit; no denominator means no coverage/share. Report stale vs current only when source dates support that distinction under an approved time rule.
4. Produce an inventory with counts by source-reported state, locator coverage, exact denominator if any, and conflicts. Never rank vendors/capacity or estimate the missing supply population.

Dedup is within a source only if a stable row/offer key exists; cross-source dedup requires a real compatible identifier and approved linkage. No tie ranking. No unapproved availability threshold, minimum stock, conversion or annualization.

## Output, example and failure

Proposed output: object/unit definition, source and locators, observation period, source-reported quantity/status, `recordCount`, `uniqueEntityCount` only when supported, missing/zero coverage, optional compatible denominator/rate, conflict list, limitations and blocker codes.

Toy fixture: three source rows each state “offer shown”; none supplies a stable offer ID or inventory denominator. Expected `locatedRecordCount=3`, `uniqueOfferCount=null`, availability `source-reported`, no supply percentage.

Blocked fixture: one source reports 12 packs and another 4 kilograms, with no conversion basis. Expected two separate partitions and `M06_UNIT_INCOMPATIBLE`; no total of 16.

## Claims, ownership and open choices

Allowed: “These N located source rows report offer/capacity state S for period P.” Cite exact file/span. Forbidden: N unique products or suppliers without IDs; available market supply; supplier ranking; complete supply or market share; unverified capacity; treatment of sales as supply.

AI role: none for entity resolution, unit conversion, classification or ranking. Human owner chooses supply object, eligible sources, timing and denominator. Depends on M02 boundary and M13 source inventory. M01 can consume only eligible exact claims.

Open parameters: supply object taxonomy, stock/capacity meaning, identity/dedup key, time freshness rule, unit conversion, denominator/universe, geography/variant. Proposed blockers: `M06_SUPPLY_OBJECT_UNDEFINED`, `M06_STABLE_ID_REQUIRED_FOR_DEDUP`, `M06_UNIT_INCOMPATIBLE`, `M06_DENOMINATOR_MISSING`. Reopen on source, unit, period or scope changes. Acceptance: incompatible kg/packs remain separate (future boundary); rows without IDs never become products (identity rule); no denominator yields no rate (output validator). All approval choices remain open.

Aggregation prerequisite: sum only a declared additive measure over proven disjoint entity/time memberships. A capacity total and component, overlapping import periods or duplicate representations must remain separate. Missing disjointness evidence blocks aggregation, not the located inventory.
