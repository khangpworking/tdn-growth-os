# M10 · Dự báo và kịch bản

Spec v1.0.0 · coverage `DRAFTED_GATE_AND_EVALUATION_TEMPLATE` · authority `PROPOSED_PARAMETERIZED_PROCEDURE; FORECAST_BLOCKED` · implementation `NO_APPROVED_MODEL_PATH` · readiness `NOT_ASSESSED` · execution/review `NOT_RUN`.

Sub-scopes: eligibility gate drafted; parameterized evaluation template drafted;
candidate baseline drafted but unapproved; executable production forecast
incomplete and blocked. None is a live approved forecasting method.

## Question and boundary

Can a specified model predict a compatible future daily series, and how does that evaluated forecast differ from an owner-authored scenario? This recipe provides a machine-executable eligibility gate and parameterized evaluation order. It emits no forecast until every model/history/horizon/split/missing/error policy is approved. Examples do not authorize any threshold or forecast model.

## Inputs

| Required for eligibility | Type / source | Choice that must be approved before fitting |
|---|---|---|
| Daily series | `{entityRef, date, timezone, metric, unit, valueState, value, sourceRef}`; exact one observation per entity/day or explicit missing | Frozen entity universe and metric meaning; period/timezone and duplicate policy. |
| History and splits | Daily date range, explicit train/validation/holdout boundaries, exact source and calculation version | Minimum history; split lengths/order and leakage rules. |
| Missing-day map | Explicit observed/missing/zero states for all calendar days under chosen timezone | Keep-missing, exclusion or approved imputation policy; no default fill. |
| Forecast policy | Versioned `modelId`, implementation digest, horizon, refit/selection rule, output unit | Model, horizon, history minimum and any error/decision threshold. None is supplied here. |
| Error policy | Chosen measures and baseline implementation/version | Metrics and treatment of zero denominators/missing holdout values. |

Separate `scenario` input is optional and must name owner, assumptions, values and period; it never enters validation results as a model forecast.

## Procedure and compatibility

1. Freeze series and universe. Sort by entity then date. Reject duplicate entity/day; partition incompatible timezone, metric, unit, universe or period definitions. Do not interpret missing date as zero.
2. Validate explicit train < validation < holdout ranges, no overlap, and horizon against the owner-supplied policy. If any policy field is missing or unapproved, emit eligibility manifest plus `BLOCKED`, with no fitted values. Current known unresolved choices: model/baseline, minimum history, horizon, timezone/day boundary, missing-day handling, split proportions/windows and error metrics.
3. Only after approval, fit each exact allowed deterministic model on train and select/refit by the frozen validation rule. Freeze selected configuration before predicting/scoring holdout; do not tune on holdout. A later production refit and future-horizon prediction require the separately declared refit policy and as-of boundary. Retain split, configuration and fit identities separately so future fitting cannot leak into held-out evaluation.
4. Emit forecast predictions and error metrics as one attempt; add separately labeled owner scenario rows without blending them into prediction. Keep uncertainty interval only if an approved model method supplies it.

No interpolation, fill-forward, seasonal assumption, extrapolation, model selection or threshold is implied. Missing holdout days are scored only under the approved policy; if no policy, the attempt remains blocked. Ties use declared model selection order or no selected model. Rounding follows model contract; raw output retained.

## Output, example and failure

Proposed fields: eligibility status, universe, series identity, gaps, split boundaries, policy versions, validation decision, forecast rows or null, actual holdout refs, error outputs or null, independent owner scenarios, blockers and limits.

Toy fixture: synthetic daily sequence has two missing calendar dates and no approved imputation, model or horizon. Expected an eligibility inventory identifying both gaps and `BLOCKED`; no forecast values are emitted.

Blocked fixture: series records use UTC one month and local time the next without an approved zone conversion. Expected separate partitions and `M10_TIMEZONE_INCOMPATIBLE`, no stitched history.

## Claims, ownership and open choices

Allowed before approval: “No forecast was computed; eligibility is blocked by …”. After later approval: report exact predicted values with held-out errors and source/model versions, separately from scenarios. Forbidden: a scenario stated as forecast, validated accuracy from training data, implied model endorsement or sales/growth prediction absent scope match.

AI role: none for model code, parameter selection, imputation, thresholds or numeric claims. Human owner approves all policy values and reviews output. Depends on compatible M03 historical observations only when separately supplied; never depends on M01 or an AI summary.

Open choices are all choices listed in inputs. Proposed blockers: `M10_MODEL_UNAPPROVED`, `M10_HISTORY_POLICY_UNAPPROVED`, `M10_HORIZON_UNAPPROVED`, `M10_SPLIT_INVALID`, `M10_GAP_POLICY_UNAPPROVED`, `M10_METRIC_POLICY_UNAPPROVED`. Reopen on any input/model/policy change. Acceptance: missing gaps produce no forecast absent an approved rule; holdout never selects model; forecast and scenario outputs have distinct labels. Implementation/approval remains future work.

## Candidate baseline recipe — PROPOSED_UNAPPROVED

This is a concrete candidate for later review, not a default or production model.
It does not set minimum history, real forecast horizon or business thresholds.

Inputs for this isolated evaluation: a compatible daily series, explicit train
end T, exact held-out dates H after T, and observed actuals. For this candidate
variant, require the training-boundary value and all evaluated actuals to be
observed; otherwise stop rather than infer a gap rule. Freeze this candidate and
MAE before looking at H. Repeated/overlapping dates reject the input.

1. Set `anchor = y[T]`, the observed training-boundary value. No fit or tuning.
2. For each held-out date h in H, set `prediction[h] = anchor`.
3. Compute exact absolute errors `abs(prediction[h] - actual[h])` in the original
   unit. Set `MAE = sum(errors) / count(H)` as an exact fraction. Empty H is
   unavailable, not zero error. Do not create accuracy percentages or intervals.
4. Retain input/date/policy pointers, anchor, each prediction/actual/error and MAE.
   No model selection, endorsement, pass threshold or business recommendation.

Toy fixture only: training-boundary value 10, held-out actuals 12 and 8 on two
explicit subsequent dates. Predictions are 10 and 10; errors 2 and 2; exact MAE
is 4/2 = 2 source units. The two-day toy horizon is not an approved real horizon
or minimum sample. Missing either actual blocks this candidate's score, without
filling zero. This example specifies expected arithmetic; it was not executed.
