# P3 handoff

Updated: 2026-10-08. Branch: `pkg/P3-pageindex-upload`.

The PDF workflow now runs through the application service and its authenticated API. A PDF attachment stores exact source bytes in a finalized Foundation package and binds it to the verified run. The collection hook retains PDF response bytes through the same path. Supplemental PDF members use that hook. Indexing remains disabled by default.

Upload attempts reserve the source SHA in SQLite before dispatch. A failed reservation makes no call. A lost acknowledgement retains the reservation, reports the call count truthfully and never uploads the SHA again. Questions likewise reserve `(run, source SHA, section)` before dispatch and count failed or uncertain attempts against the durable run cap. Repeating REPORTS preserves previously stored verified quotes.

The run worker extracts exact finalized PDF bytes with the existing bounded local `pypdf` script. Only page-matched quotes enter registered run artifacts with `EXTERNAL_VERIFIER_ATTESTED`; raw answer text never enters a report or the quote artifact. Rendering these quotes is still P8's task.

The source card reads key presence, durable call history, upload counts and an estimated balance. Unknown credit, unreadable lists and unknown page counts remain unknown and pause spending. Storage accrues over calendar months above the shared 1000-page allowance. The upload gate also accounts for the proposed indexing charge. An explicit owner recheck performs only the free document-list call. GET states/status performs no provider call and no database mutation.
