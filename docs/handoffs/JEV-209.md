Sidecar decision:

The sidecar route was selected because `filterKeywordMeanings` is already the deterministic L9 contract and the existing TikTok/web packets validate that contract directly. Changing `keyword-meaning-filter.schema.json` would require regenerating report validators owned by another lane and would mix model decisions into the deterministic replay. The new sidecar keeps normal L9 replay intact and lets callers apply gate outcomes to their own disposition/count projection.

Owner decisions applied:

- “Jev is TypeSafe's decision model: it answers typed choice questions about a given state with a choice, per-option probabilities and a confidence.” The client sends typed choice questions and validates every answer before use.
- “Only records with decision UNCLEAR and reason `NO_KEYWORD_MATCH` or `UNRESOLVED_UNDIACRITICIZED` go to Jev.” The candidate selector enforces this boundary.
- “Off (default): output must be byte-identical to today.” The optional sidecar is absent when disabled; deterministic TikTok/web paths retain their existing fields and reasons.
- “Jev failing (network, HTTP, invalid answers): keep the deterministic L9 result, record a run note such as `L9_JEV_UNAVAILABLE`, and never fail the run.” Client failures produce no decisions; the sidecar records `L9_JEV_UNAVAILABLE` and the applied projection falls back to deterministic L9.
- “Reader-facing text never names Jev, TypeSafe or any data provider.” The sidecar uses the machine-label reasons `đúng sản phẩm (máy phân loại)` and `không nói về sản phẩm (máy phân loại)` only for downstream appendix rendering.
