## Delivered

I02/I04/I05/I07/I08 now share the existing source-bound proposal, explicit
receipt, immutable report revision and verified historical replay path with
I06/I09/I10/I13. This removes a delivery gap before connecting model proposals:
the earlier path could not admit or select these five semantic families.

The proposal contract accepts the five additional arrays together, including
explicit empty arrays. Selection v2 requires indexes for all families. A proposal
containing the new families cannot be accepted with a legacy v1 receipt. Unchosen
declarations become pending in the calculation projection, not accepted evidence.
Exact source text, context, qualifiers, counterevidence and corpus membership stay
unchanged. Existing method owners still validate spans, relationships and codes.

Legacy proposals/receipts retain their v1 calculation behavior. A v2 report
snapshot records its selection version; the renderer uses selected semantic
output instead of accidentally displaying the earlier literal projection. The
source snapshot remains retained. New v2 Insight uses renderer v10; legacy
Insight remains v9. No existing migration or calculation formula changed.

The existing review panel displays the additional candidates, their source
declarations and qualifiers, supports exact checkbox selection and explicit
confirmation, and verifies the receipt after reload. It does not generate these
candidates itself. The manual editor still authors its original four families;
an expanded saved proposal can be copied, retained and have individual entries
removed without silently dropping its other families.
