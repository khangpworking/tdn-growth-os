# Research A11: verified report history in the local operator

## Objective

Expose the immutable A10 report ledger through the existing Fedora-local
operator without changing report calculations, adding AI, or creating a review
decision. An OWNER can discover report series for one market workspace, replay
one series, explicitly choose a version, and open the exact persisted HTML and
evidence files.

## Required behavior

- Keep SQLite read-only, file-must-exist and `query_only` for every report read.
- List report series by exact discovery-workspace ID through an Analysis-owned
  catalog reader. Catalog presence is not presented as verification.
- Replay and verify every version before returning history. Preserve explicit
  predecessor order; never select the latest version implicitly.
- Serve only a strict basename that is a member of the replay-verified report
  version. Never accept a filesystem path or expose the artifact root.
- Serve `report.html` inline with a script-free CSP and all other files as
  downloads. Relative links in the immutable HTML must resolve to the same
  verified artifact route.
- Show honest loading, empty, connection and integrity states. Demo mode must
  not fabricate a report.
- State the current truth: four partial deterministic section drafts out of 30,
  AI interpretation `NONE`, human review `UNREVIEWED`.

## Four-layer boundary

1. Source evidence remains the exact source-package bytes and locators frozen by A10.
2. Calculations remain the deterministic packet and charts already generated by code.
3. AI interpretation remains absent; this task does not make a provider call.
4. Human decision remains absent; this task exposes no approval control.

## Storage clarification

Normalized rows are currently retained as exact content-addressed report
artifacts whose identities and membership are persisted in SQLite. A11 reads
those verified artifacts; it does not claim row-level normalized observations
are queryable as SQLite rows. That separate persistence slice remains next.

## Explicit exclusions

- No fifth section method or change to the 30-section business framework.
- No report generation or mutation endpoint.
- No AI interpretation persistence, human review ledger or PDF renderer.
- No public/domain exposure, auth-policy change, deployment, migration or real data import.

## Verification ownership

- The report service test owns series lookup and exact member reads.
- One HTTP integration owns route validation, verified history, exact bytes,
  security headers and corruption failure.
- Frontend data-source tests own the closed response shape and predecessor chain.
- One mounted component test owns explicit version choice before report access.
- Linux CI is the typecheck/test/build gate; no Windows tests/build/typecheck.
