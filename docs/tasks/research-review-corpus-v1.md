# Research automation raw review corpus v1

Assigned checkout: research-automation-v1. This is the bounded raw admission prerequisite for parallel Market/Insight collection. It adds no provider activation, paid-run authority, semantic method, category codebook, calcium policy, migration, UI or report wiring.

`buildResearchReviewCorpus(VerifiedExactShopeeCollection)` returns `{output, bytes}` under `research-review-corpus-v1` with frozen literal mapping `apify-shopee-review-row-v1`. `verifyResearchReviewCorpus(snapshot, verifiedCollection)` rebuilds against the reread collection, without provider calls or database writes. Root owns schema registration and integration; source-package intake is a later consumer of the existing retained collection, not a third raw ledger.

The caller must obtain its input through Foundation's `readExact`/`saveExact` boundary. This builder independently checks canonical packet SHA, exact selection replay, actor-input SHA, page membership/digests/sizes/offsets, total/per-listing bounds and reported-row totals. It cannot authenticate a provider or replace the Foundation database/manifest reader. Original request SHA remains the exact-byte digest verified by Foundation; the normalized request object is not falsely rehashed as original bytes.

Literal mapping reads only `shopId`, `itemId`, `reviewId`, `comment` and `ratingStar`. It projects full unchanged comment strings and exact page SHA/page index/row index/row/comment JSON Pointers. Raw-row canonical SHA retains full-content identity without projecting usernames/author metadata. Original date/variant and every unmapped field remain resolvable through the raw row reference; no normalized date, variant, person, hearsay, category, theme or semantic annotation is invented.

Every returned raw row has a represented occurrence. Known but wrong listings and unresolved listing identity are visibly quarantined, not discarded. Invalid or missing rating never discards readable text. Empty/unreadable comments retain their state and row references. Native IDs are preserved as bounded original strings or exact safe positive numeric IDs converted to strings. Only an absent ID receives an internal collection/page/row locator; present-but-unusable IDs remain UNRESOLVED without a fabricated native or internal identity. Missing listing identity never merges native IDs across unidentified listings.

Same native ID plus exact observed listing identity collapses only equal full canonical row content, retaining every source reference and occurrence count. Distinct content at that identity remains unresolved versions with conflict status. Distinct IDs with the same text remain distinct records; ID-less occurrences never collapse by text. Canonical row hashing considers all source fields, so differing unmapped fields conservatively remain a conflict rather than being silently ignored.

Capture actor status/stop reason/warnings and literal record statistics are retained separately from `RAW_CAPTURE_ONLY` and `NOT_CODED`. Counts describe returned records, not unique people, product-use admission, coding completeness, prevalence or source-market coverage. I03/I17 may use this source/corpus account and exact raw quotes; no complete I03/I10/I17 section or full report is claimed.

Bounds reuse at most five selected listings, the collection's existing maximum 500 rows/listing, 25 raw pages and 8 MiB/page. A corpus output above 8 MiB fails explicitly with `REVIEW_CORPUS_OUTPUT_TOO_LARGE`; no text/row/qualifier is shortened or silently dropped. The complete collection remains retained for a blocked or partial downstream operation.

Test-audit authoring gate: four primary owner cases protect row conservation/quarantine/privacy, native-ID duplicate/conflict semantics, source integrity/replay and explicit output bounds. Fixtures use actual ShopeeCollectionService, all migrations, CAS and FixtureShopeeCollector so the source receipt is produced by its real owner, not hand-invented. Expected texts, counts and pointers are independent synthetic values. No test-only production seam or duplicate lower-layer proof is introduced.
