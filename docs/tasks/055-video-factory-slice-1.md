## 2. Checkpoints

Each checkpoint is a separate small PR that must be green on CI before the next starts. Test rows are numbered T1, T2, … across the whole slice. Each test row states what to prove and its negative control (the case that must fail). The Sol test writer writes these tests; each exercises its negative control at the intended guard (task 2.11 of `video-factory-v1`). T2–T4 are cases in one lock-boundary suite; do not duplicate that proof across layers. Checkpoint 1 proves relaunch with the fake runner (T5); checkpoint 2 provisions/hardens real media processing before the library uses it; checkpoint 3 extends the same fixture to rendering.

### Checkpoint 1 — schema, worker, sweep, fake runner, safe takeover, relauncher

Owned paths: `migrations/0060_*.sql` and next allocated numbers; `src/modules/flow/video-service.ts`, `video-jobs.ts`, `video-worker.ts`; `src/api/executor-lock.ts`; `src/api/operator-app.ts` (startup and wiring); `src/platform/video-process-runner.ts` and the other copied helpers; `deploy/systemd/user/tgos-operator.service`; `docs/runbooks/fedora-local-operator-runtime.md`; `.github/workflows/check.yml` (disposable relauncher fixture); `src/api/executor-lock.ts` comment update. The shared lock and restart change may land as its own small PR inside 055 (054 §7 sequencing note).

Closes rows: 055-Q1 (state/schema), 055-Q2, 055-Q3, 055-Q7, 055-Q17 (relaunch fixture), 055-Q18, 055-Q19.

Test rows:

- **T1** — Startup sweep: parameterize import/voice/render jobs left running by a dead executor; all become interrupted with restart reason before serving, without a new dispatch. Negative control: succeeded/failed/cancelled/queued rows remain unchanged, and a read-only operator never sweeps.
- **T2** — Two starters race after a proven-dead owner: exactly one acquires executor authority and writes; the loser exits held-lock. Force the delayed loser to resume after the winner has replaced the lock. Negative control: it must not rename/delete the winner's lock or write; with a live owner both contenders are refused.
- **T3** — A same-host valid proven-dead lock permits takeover. Negative control: other-host, unreadable/corrupt and legacy metadata without process identity all fail held-lock, leaving the existing lock unchanged and no writes.
- **T4** — An absent recorded PID on the same boot can pass the death proof. Negative control: reuse that PID for a different live process, or make boot/start identity unreadable; takeover stays manual and never signals the unrelated process.
