# Source intake in scope confirmation

Mode: Operate. The owner decides the exact research scope and which retained
source may enter its first report. Upload stores evidence; confirmation admits it.
This is a narrow extension of the existing scope screen, not a redesign.

## Direction contract

THESIS: Make storage and report admission visibly separate. Never imply that
uploading starts research or that a recently uploaded file is selected by default.

OWN-WORLD: Keep the approved navy, white and blue TDN system, existing fields,
focus rings and section spacing. No new imagery, typography or navigation.
ENERGY 1 / RHYTHM 1 / MOTION 1. Repeated controls serve this decision form.

STORY: Read saved sources, choose an exact compatible file or explicitly proceed
without one, then confirm the scope and source choice together. Dates and precision
are owner declarations, not authenticated provider metadata.

FIRST VIEWPORT: Preserve the existing product and scope controls. Place the source
section before the final confirmation, with a compact selector and an expandable
upload form. Keep the final blue confirmation action as the primary action.

FORM: Inherited scope form; no concept seed applies to this local extension.
The signature interaction is a saved-source receipt that still requires selection.
Uncertain uploads retain their exact retry snapshot; scope edits cannot slip into it.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Boundaries and acceptance

No provider call on typing, selecting a source, uploading or reloading inventory.
No automatic latest selection. Changed scope makes the old file incompatible.
Stop waiting cannot promise to undo server storage. Tokens remain in memory.
Inspect desktop and mobile, keyboard, empty/loading/error, exact retry and stale
response behavior before release. A late source uses a separate version flow;
this first extension does not yet provide that flow.
