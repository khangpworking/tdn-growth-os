# Insight coding in report versions

Mode: Operate. Local extension of the existing research dossier and version panel,
beside Metric classification. The owner approved separate rule adoption, proposal,
selected acceptance and report creation (handoff `research-b2-insight-coding.md`).

## Direction contract

THESIS: Every code points back to words the source actually wrote. The owner picks
a quote occurrence in the unmodified record; the screen carries offsets and IDs.
Adopt, propose, accept and create report are four separate confirmations.

OWN-WORLD: Inherit navy text, white surface, blue primary buttons and teal focus
from DESIGN.md. Native fields, details and ConfirmDialog; record text in a quiet
paper well with pre-wrapped original spacing. No imagery or new font.
ENERGY 1 / RHYTHM 1 / MOTION 1.

STORY: Read the bound source records, choose or draft a rule (question, inclusion,
adjudication, optional I10/I13 corpora with explicit members and a blank codebook),
adopt it, draft I06 journeys, I09 gaps, I13 literal mentions and corpus codes from
exact quotes, save one proposal, tick the items to accept, then explicitly create a
report version from chosen receipts. Reload reads history; it never resubmits.

FIRST VIEWPORT: Version and source binding in plain words, source record counts by
inclusion state, then explicit rule and proposal selectors. History stays read-only.
Editors open on demand under the selected rule; nothing is chosen for the owner.

FORM: Extend the version panel with one toggle, no new navigation or concept seed.
The signature is the quote-occurrence picker: type or highlight a quote, see each
occurrence with its surrounding words, choose one. Frozen confirmation/retry
snapshots reuse the Metric pattern. Missing, excluded and unreadable records,
pending items, unresolved disagreements, stale rules and integrity failures each
get their own wording and next action.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Boundaries

Rules, corpora, codebooks and provenance start blank; no industry label, segment,
demographic or code is suggested. Corpus membership, completeness and multi-code
are explicit owner choices; acceptance never shrinks a corpus and pending stays
pending, never zero. Provenance is a declaration, not authorization. The proposal
chain token (`previousProposalId`) and acceptance digest come from the explicitly
selected history item and are shown in readable words in confirmations. Report
creation reuses KEEP Metric and KEEP review, needs the latest proposal of a current
rule, and lists the chosen receipts. Uncertain writes keep the exact request and
key in memory for explicit retry. Owner token stays in memory; no browser storage.
